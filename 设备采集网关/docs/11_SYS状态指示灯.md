# SYS1～SYS3状态指示灯（软件0.8.2）

2026-11-09补充：软件0.8.0未授权或授权不匹配时，SYS3按严重异常常亮；管理网页保留，南北向测量与控制不启动。须先完成本机永久授权，再人工重启程序。

> 2026-10-29更新：软件0.5.0／V3.2-D2新增远程液位修改。网页“历史与诊断”可输入目标液位；上位机先向J=31000+4×(n−1)用FC10写目标高/低字，再向原C+0写11提交，沿用C+1状态和C+2错误。按FW9000NN资料实时读取IR0/1、HR503/504，用HR129=0xEA66认证，修改后清零认证；不向HR699写11或512。具体操作及板端验收见[远程液位修改说明28](28_远程液位修改与验收说明.md)。64台容量及原浮子动作不变。


V1.8资料包中GT6757规格书第12页说明三灯可编程；Buildroot V1.3第22页、Ubuntu V1.0第16页映射SYS1=/dev/led、SYS2=/dev/led2、SYS3=/dev/led3。Go LED例程写ASCII“1”亮、“0”灭。已按此实现。2026-10-16用户明确确认本台实体SYS灯驱动正确，登记为已确认；依据见[现场确认](../source_notes/SYS实体指示灯驱动确认_20261016.md)。全部故障模式覆盖及长时间运行记录继续分别填写，不重复要求验证驱动本身。

控制终态锁存，因此4/5可保持SYS3常亮直到记录处理并复位；独立停止确认不能清除正常未知。北向整机22～24读软件灯态，25驱动启用、26驱动错误；软件灯态不证明实体灯点亮。网页显示同一状态。

启动默认启用；--leds=false或service.env LEDS=0关闭实体控制。模拟只展示虚拟灯态，不打开电脑设备。驱动打开/写失败记录事件并保持采集，不把错误当作成功。

板端需检查厂商自启服务是否同时写SYS1；由维护人员确定唯一驱动方后配置，程序不会自行停止不明厂商服务。TX/RX灯仍由串口硬件表示收发，不受本应用控制。看门狗只有实测驱动后启用。

0.3.2的时间警告取决于真实校时及RTC检查结果，不再使用TIME_TRUSTED强行设定。网页校时保存RTC、重启检查及失败诊断见[说明23](23_时钟校核与断电恢复.md)。


## 网页运行诊断

0.8.2 起，“历史与诊断 → 运行诊断”分别展示 SYS1 程序运行、SYS2 液位计采集、SYS3 告警。每张卡片显示当前灯态、闪烁周期和运行含义。SYS2 同时显示已启用台数和快速采集正常台数。

“实体灯控制 · 已启用”表示程序已打开三路硬件驱动，并按计算的灯态持续控制实体灯。软件根据驱动打开及写入结果判断此状态，实体灯实际亮灭需要现场观察。“未启用”时查看部署配置及运行事件。“驱动异常”会显示打开或写入失败的原因。“模拟运行”表示页面展示软件计算的灯态。

“当前告警原因”列出当前触发 SYS3 的原因，严重告警和一般告警可同时存在。采集异常尽量显示 COM 口、仪表地址、槽位、名称、寄存器组和最近错误。控制失败与结果不确定分别提示动作、独立停止及槽位，便于在控制结果中核查。其他原因包括时间未确认、参数快照读取失败、存储、控制记录恢复、串口运行和实体灯驱动异常。

SYS2 常亮而 SYS3 慢闪时，请直接看告警原因。例如快速数据正常，但参数快照读取失败或采集时间未确认，也会使 SYS3 慢闪。某次失败已恢复后，累计失败次数仍会保留，告警原因按当前状态更新。维护模式下 SYS2 熄灭，暂停产生的快速数据过期不作为采集告警列出，仪表故障及其他既有异常仍按原规则显示。

实体灯含义、闪烁周期和北向寄存器编码沿用原规则。授权过渡包仍用于 0.6.0 样机先办理授权、再安装 0.8.1。取得授权并运行 0.8.1 后可通过网页升级到 0.8.2。


## 告警明细展开与收起

0.8.2-20261117-r1 网页修订版中，“当前告警原因”默认收起，标题显示当前告警数量。点击标题可展开，再次点击可收起。每两秒数据更新时保持当前展开或收起状态，列表及数量继续更新。重新加载网页后恢复默认收起。

软件0.8.3允许仪表有故障码时下发已开通的操作和独立停止，仪表自身判断是否执行。网关根据通讯应答及指令回读确认控制结果，故障字、质量告警和SYS3告警按实际情况继续显示。旧状态4／错误3保留，可经人工核查后复位，再提交新动作。
