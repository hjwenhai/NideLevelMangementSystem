# 网络设置与失联恢复

软件0.8.1，安装包0.8.1-20261109-r1。适用于本项目厂家Buildroot系统的GT6757S。以下是软件操作说明；真实网口切换、FUN按键和断电保留须按第8节上板验收。

## 1 网页怎么修改

1. 电脑连接网关，用当前IP和原网页端口登录管理员页面，进入“系统维护 → 网络设置”。
2. 点击“重新读取网络参数”，记录两个网口的原地址。修改前先处理完控制操作，并人工核查、复位已有控制结果。
3. 填写网口1（eth0）和网口2（eth1）的IP、子网掩码。两个子网不能相同或重叠；地址要避开现场其他设备及路由器DHCP地址池。
4. 默认网关只在需要跨网段通讯的一个网口填写；另一个留空。同网段直连时可以都留空。默认网关须为该网口子网内的路由器地址。留空的网口在厂家配置文件中禁用GATEWAY项，不把0.0.0.0作为实际路由网关。
5. 选择Modbus TCP接入网口。一般选上位机所在网口；若选“两个网口”，两个IP均可接入。原TCP端口、站号、连接数和控制许可不变。网页可从两个网口访问，原网页端口及HTTP/HTTPS方式不变。
6. 勾选影响确认，点击“应用并试用网络设置”。此时只受理试用，不是最终确认。程序短暂停止并重启，采集、网页、TCP和北向RTU通讯都会短暂中断；不会给浮子发送停止或其他动作。
7. 点击页面提供的新地址链接，必要时把电脑改到新子网。新IP需要重新登录。页面会进入网络设置；核对两个网口参数、实际地址及上位机连接。
8. **试用开始后180秒内**，勾选“已通过新地址连接，核对网络及上位机通讯正常”，点击“确认保留本次网络设置”。等状态显示“网络设置已确认并保存”后完成。

180秒从执行器准备启动新服务时开始，包含新服务启动时间。网关使用单调计时，网页显示的日历截止时间供参考。确认必须由人操作，程序不会自动替客户确认。服务端依据实际接入网页的本机IP判断，不能用修改浏览器Host或代理头代替新地址连接；建议直接访问IP，不经反向代理。

试用期间未确认、断电或重启，下次启动前恢复修改前的网络及监听配置。确认后参数保存在系统文件中，正常断电重启继续使用。修改期间禁止新控制、控制结果复位、配置写入、校时、密码修改、程序重启和应用升级，读取与已恢复服务的采集继续运行。

## 1.1 接入网口、服务端口和只读访问地址

从0.8.1起，只在本页选择Modbus TCP接入网口，不在两处重复填写IP。

| 页面 | 可以修改 | 显示内容 |
| --- | --- | --- |
| 系统维护→网络设置 | 两网口IP、掩码、默认网关、Modbus TCP接入网口 | 当前实际网口地址、网络试用与确认状态 |
| 端口与仪表 | TCP服务端口（默认502）、站号、并发连接数、启用及写许可 | 接入网口、上位机连接地址及复制按钮；IP只读 |

例如：网口1为192.168.1.230，网口2为192.168.0.230，服务端口502。选择网口2时显示192.168.0.230:502；选择两个网口时分别显示192.168.1.230:502及192.168.0.230:502，可复制给上位机配置。0.0.0.0表示程序绑定所有IPv4网口，不是客户应连接的地址。

只修改服务端口时，在“端口与仪表”保存并应用；TCP连接会短暂中断，上位机须改用新端口，网页地址不变，不需要网络试用确认。改变IP或接入网口仍按第1节试用并在180秒内人工确认，原服务端口保留。

下方访问地址显示已保存的运行配置，不随未保存的端口输入改变。程序或其他管理员更新配置后，无本地未保存修改时自动读取新参数；存在本地修改时保留草稿，保存遇到版本冲突应重新加载网页。TCP关闭或设备未授权时，页面明确提示服务未开放，显示地址不代表可以连接。

电脑浏览器与部分手机在HTTP下不允许自动写剪贴板，程序会尝试复制；仍失败时显示选中的文本供长按复制。复制不保存或修改参数。

导入其他网关配置时，保留本机当前TCP接入IP／双口方式，只导入服务端口及其他原有仪表、采集和服务参数，并提示用户检查后保存。后台普通配置接口也拒绝改IP，不能通过改JSON绕过网页入口。为兼容旧版本，配置文件仍使用tcp.listen保存组合地址，未改变schema3或北向点表。

如果两个网口的实际地址暂未读到，会明确提示并按保存配置显示；没有任何可用地址时不生成0.0.0.0复制项。旧设备存在异常绑定IP时，由厂家按Console恢复步骤修复，不能把未知IP自动改成开放双口。

## 2 多个网关怎么分配地址

通过交换机接上位机，每台设置不同IP。以下仅为规划示例，不能与现场已有设备重复。

| 设备 | 业务网口eth1 | 维护网口eth0 | Modbus TCP |
| --- | --- | --- | --- |
| 上位机 | 192.168.0.100 | — | 分别建立各网关连接 |
| 网关1 | 192.168.0.230 | 192.168.1.230 | 192.168.0.230:502 |
| 网关2 | 192.168.0.231 | 192.168.1.231 | 192.168.0.231:502 |
| 网关3 | 192.168.0.232 | 192.168.1.232 | 192.168.0.232:502 |

示例掩码均为255.255.255.0。同一网关两个网口不桥接、不自动转发。不同网关的Unit ID都可为1，槽位都可从1开始；上位机按“网关IP＋槽位”区分液位计。未改IP的新设备逐台接入，不能把同默认IP的多台设备同时接入网络。

## 3 改错、失联或忘记IP

### 3.1 刚修改后打不开

先检查电脑是否切到新子网、网线是否接对，以及页面端口是否仍正确。无法确认时不要反复提交，也不要自动写入旧参数。等待试用结束，程序会恢复修改前参数；随后通过原IP重新登录查看结果。试用期间断电的设备在应用下次通过service.sh启动时恢复原配置。

### 3.2 忘记已保存的IP：使用厂家FUN临时恢复

1. 断开其他网关与现场网络，电脑直连本台，避免默认IP冲突。
2. 等设备正常进入系统。**不要按住FUN再上电**，这可能进入厂家文件系统更新流程。
3. 长按FUN约3秒。厂家资料说明会出现指示灯/蜂鸣提示，并临时恢复两个网口地址。
4. 连接网口1时，电脑设为192.168.1.100/24，打开 `http://192.168.1.230:8088`；连接网口2时，电脑设为192.168.0.100/24，打开 `http://192.168.0.230:8088`。若网页端口或HTTPS方式曾修改，使用实际端口与方式。
5. 用原管理员密码登录，在“网络设置”查看保存的地址与当前实际地址。记录地址，或重新按第1节修改并确认。

**FUN只临时恢复IP，不清除密码、仪表绑定、历史或控制结果，不停止浮子。** 重启后仍使用保存的IP；未确认的试用例外，会恢复试用前配置。TCP如绑定保存的特定IP，FUN恢复期间可能无法连接；先从两个网口均监听的网页处理，不以TCP能否连接判断FUN是否成功。

本程序不读取或接管/dev/key，不修改/etc/reset.conf，不关闭厂家sysrst服务。网页只能检测相关配置是否存在，不能代替实际按键验收。若原厂服务已被停用、定制或故障，FUN恢复不一定生效，应使用Console。

### 3.3 FUN无效：通过Console查看

将设备Type-C Console UART接电脑，按说明17使用115200、8N1、无流控，登录设备系统。以下命令均在设备终端执行，不需要知道当前IP。

```sh
# 查看网口1当前实际IPv4地址。
ip -4 addr show dev eth0

# 查看网口2当前实际IPv4地址。
ip -4 addr show dev eth1

# 查看默认路由与出口。
ip -4 route show

# 查看网口1保存的静态网络参数。
cat /etc/net.conf

# 查看网口2保存的静态网络参数。
cat /etc/net2.conf

# 检查厂家FUN服务是否运行；无结果时需核查系统启动配置。
ps | grep '[s]ysrst'

# 查看厂家FUN恢复操作是否被定制；这里只查看，不执行文件内容。
cat /etc/reset.conf

# 查看网络事务、确认与恢复日志。
tail -n 100 /home/level-gateway/logs/network.log

# 查看独立网络执行器日志。
tail -n 100 /home/level-gateway/logs/network-worker.log
```

查到实际IP后，电脑设同子网地址并登录网页。如试用执行器已异常退出，先确认无安装、升级或活跃网络执行器，再在允许中断的维护窗口执行：

```sh
# 停止应用监督器，避免恢复时应用继续读取中间配置；不停止浮子。
sh /home/level-gateway/current/deploy/service.sh stop

# 恢复未确认或中断的网络事务；仍在运行的网络执行器会使本命令拒绝执行。
/home/level-gateway/current/bin/gateway-core --network-base /home/level-gateway --network-recover

# 前一条恢复成功后启动应用，重新核对网页、TCP和仪表采集。
sh /home/level-gateway/current/deploy/service.sh start
```

若恢复报告文件损坏、路径不符或写入失败，保留日志与备份，由厂家核查；不要删除事务记录、修改校验内容或覆盖数据库来绕过。

## 4 持久化、备份和日志

| 文件 | 作用 |
| --- | --- |
| /etc/net.conf | 厂家eth0固定IP、掩码与默认网关；METHOD=STATIC |
| /etc/net2.conf | 厂家eth1固定IP、掩码与默认网关；METHOD=STATIC |
| config/gateway.json | 同步更新tcp.listen及配置修订号，保留槽位与仪表绑定版本 |
| config/service.env | 网络修改时WEB_LISTEN同步为0.0.0.0:原端口；其余已有设置保留 |
| data/network-state.json | 网络事务、原文件快照、确认状态和恢复依据；属于运行数据 |
| data/network-backups/任务ID/ | 每次修改前四个文件的独立备份，保留供厂家核查 |
| logs/network.log、network.log.1 | 申请来源、目标参数、人工确认及恢复记录，单文件约1MiB后轮转 |
| logs/network-worker.log | 独立执行器启动与服务启停问题 |

config/data/logs均相对于/home/level-gateway。客户文档不部署设备。0.7.0通过项目supervise.sh启动时，管理网页在全部IPv4接口监听原端口，即使WEB_LISTEN仍记录旧IP也能通过FUN临时地址访问；第一次网络修改后文件中也保存此监听方式。IPv6、DNS、DHCP、VLAN、桥接、自定义静态路由不在本版设置范围。

系统文件成对修改使用事务快照保护；在两个文件中间掉电，下次service.sh启动也会恢复。独立执行器不随core/web一起停止。确认后启动按厂家bootset及ifconfig-eth0/eth1脚本读取系统文件，须保留厂家网络启动流程和项目自启入口。

## 5 首次安装与升级

先按说明10完成原有手动或向导安装，使用已有IP接入；安装本身不改变网口IP。新版服务启动后出现“网络设置”，再按本说明修改。设备文件仍为16项，新增功能编译进原core/web，不额外上传文档或厂家资料。

已部署0.6.0网页升级基础版的设备，可上传对应架构的0.7.0-20261108-r3.gwup。升级保留现有IP，不自动重新编号；网页监听扩大到两个IPv4网口。原HTTP/HTTPS、密码及TCP权限不变。确认厂家sysrst已启用后验收FUN恢复。

HTTPS证书必须覆盖新IP或使用相应有效域名，否则浏览器会报证书不匹配；本功能不自动更换证书。默认仍使用HTTP，看门狗仍关闭，不增加整机重启。

## 6 适用范围与拒绝条件

要求厂家Buildroot布局、eth0/eth1、/etc/net.conf和/etc/net2.conf、静态地址、root运行权限和可用ip工具。DHCP、多个IPv4别名或特殊路由应先由厂家整理，不自动覆盖。两个网口均不能为空或停用；掩码支持连续/1～/30。程序不保证自动识别其他设备的重复IP，必须提前规划并通过试用验收。

当前程序不校验客户是否已停止机械动作，操作人员须确认现场允许中断。网络设置不修改液位计站址，也不发送H129或其他南向写入。

## 7 已完成的软件检查

验证范围包括参数校验、监听联动、人工确认、真实180秒试用超时、应用启动失败恢复、分步写入中断恢复、持久化门槛、账号与绑定保留、控制和维护互斥、网页认证与来源校验。结果以本次交付记录为准，不能把Windows模拟配置文件当作板端网口测试。

## 8 上板验收清单

| 项目 | 操作与合格条件 |
| --- | --- |
| 两网口及网页 | 分别连接两个物理网口，用当前IP登录；页面eth0/eth1与面板网口一致 |
| 新地址确认 | 改两个IP、合法掩码和一个默认网关；新地址重新登录确认，两个实际地址及TCP监听正确 |
| 跨网段路由 | 从规划的上位机网段验证请求和回复；默认网关只在正确出口存在 |
| 断电保留 | 确认成功后断电再上电，新IP保留，网页和采集恢复 |
| 超时恢复 | 不确认，180秒后原地址恢复；TCP、RTU与采集均恢复 |
| 试用中断电 | 已切新IP但未确认时断电；开机恢复原地址，控制不重发 |
| FUN恢复 | 系统启动后长按FUN约3秒，直连单台验证两个临时默认IP和网页登录；重启回保存IP |
| 配置和记录 | 修改前后核对密码、槽位、名称、地址、控制权限和历史；均保留 |
| 错误输入与互斥 | 同子网、非法掩码、双默认网关、未复位控制及升级中修改均被拒绝 |

验收应在隔离调试网完成，记录本机固件、应用版本和实际结果，再接入现场网络。
