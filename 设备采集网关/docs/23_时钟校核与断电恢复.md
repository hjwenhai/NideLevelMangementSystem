## 1 本次解决什么问题

旧程序网页校时只确认当次运行，未保存RTC，重启后再次显示时间未确认。新版保存校时记录和UTC硬件时间；下次启动检查通过后自动显示“设备时间已确认（RTC恢复）”。

首次升级仍须在网页校时一次，让新版形成记录。不能直接沿用旧程序的内存标志。RTC不存在、保存失败或检查异常时，继续采集并提示具体原因，不把旧时间标成可信。

## 3 确认RTC节点并允许校时

0.3.3安装器会保留service.env已有值并补齐缺失支持项，包括RTC_DEVICE。0.3.2旧安装器则原样保留文件，不自动添加参数。运行时缺少RTC_DEVICE仍默认/dev/rtc0，所以缺少这一行本身不代表程序没有升级。以下步骤用于核对实际路径并开通RTC校时。

以下在**设备SSH或Console终端**执行。若RTC节点与示例不同，先核实哪个是板载后备电池时钟，再填写实际路径；多RTC设备不要逐个尝试写入。

~~~sh
# 查看设备实际提供的RTC节点。
ls -l /dev/rtc*

# 查看rtc0芯片名称；文件不存在时先核对驱动和实际RTC编号。
cat /sys/class/rtc/rtc0/name

# 查看当前系统UTC时间，与电脑当前时间核对。
date -u

# 备份本次修改前的服务配置，备份名包含UTC时间。
cp /home/level-gateway/config/service.env "/home/level-gateway/config/service.before-rtc-$(date -u +%Y%m%dT%H%M%SZ).env"

# 允许网页修改系统时间、保存RTC，并允许开机根据RTC恢复系统时间。
sed -i 's/^ALLOW_CLOCK_SET=.*/ALLOW_CLOCK_SET=1/' /home/level-gateway/config/service.env

# 原配置已有RTC_DEVICE则修改，没有则补上；本例只适用于已确认的rtc0。
if grep -q '^RTC_DEVICE=' /home/level-gateway/config/service.env; then sed -i 's|^RTC_DEVICE=.*|RTC_DEVICE=/dev/rtc0|' /home/level-gateway/config/service.env; else printf '\nRTC_DEVICE=/dev/rtc0\n' >> /home/level-gateway/config/service.env; fi

# 确认两项配置均正确；若ALLOW_CLOCK_SET行缺失，先补齐再重启。
grep -E '^(ALLOW_CLOCK_SET|RTC_DEVICE)=' /home/level-gateway/config/service.env

# 重启应用以读取配置，采集会短暂中断；本条适用于本台Buildroot的PID监督方式。
sh /home/level-gateway/current/deploy/service.sh restart
~~~

应看到`ALLOW_CLOCK_SET=1`和`RTC_DEVICE=/dev/rtc0`。升级不会改变原`WEB_LISTEN`，本台应继续使用已验证的维护地址。旧`TIME_TRUSTED`即使还留在配置中，新程序也不使用；不能用它代替真实检查。

systemd固件应修改实际core服务参数，增加`--allow-clock-set --rtc-device /dev/rtc0 --clock-state /home/level-gateway/data/clock-state.json`，再使用systemd重启；不混用本节PID脚本。本台Buildroot无需执行systemd分支。

## 4 网页校时一次

1. 先确认电脑/平板的日期、时区和当前时间准确。
2. 打开`http://192.168.0.230:8088`，必要时强制刷新页面，登录原管理员账号。
3. 在“历史与诊断 → 运行诊断”点击“用此电脑／平板时间校核网关”。
4. 确认显示“电脑/平板校时成功，已写入RTC并回读确认”和“RTC已保存”。等待下一轮采集，快速组的`time_trusted`陆续变为true；慢速详情组等自己的下一次采集。

若提示“本次时间已确认，但RTC未保存”，仅代表当次运行有效，下次冷启动不能自动确认。原因会显示在同一位置，需检查节点、权限、驱动及后备电池，不能只看页面顶部已确认就结束验收。

部分RTC驱动不提供电池/数据失效标志。此时程序仍核对日期、写入回读及开机走时，并提示“后备电池仍需断电验收”；不把“不支持读取电池标志”当成电池正常证明。

~~~sh
# 查看必要校时记录，核对rtc_saved为true、invalidated为false。
cat /home/level-gateway/data/clock-state.json

# 读取RTC的UTC日期，不改动硬件时间。
cat /sys/class/rtc/rtc0/date

# 读取RTC的UTC时刻，与系统UTC时间及电脑实际时间核对。
cat /sys/class/rtc/rtc0/time
~~~

网页显示北京时间时，比RTC的UTC时刻快8小时属于正常换算。不要再把RTC手动写成北京时间，否则下次可能差8小时。

## 5 进程重启和断电复测

先保证现场没有正在进行的动作或未完成的控制操作。保持正常采集至少2分钟，让时间检查点完成保存，然后测试：

| 步骤 | 操作 | 通过标准 |
| --- | --- | --- |
| 进程重启 | 执行下方restart命令，再访问网页 | 无需再次点击校时，显示“设备时间已确认（RTC恢复）”；新采集组为true |
| 断电恢复 | 记录电脑时间；设备断电约1分钟后重新上电；确认原自启入口有效 | RTC包含断电期间的流逝时间；网页时间与电脑相符，自动确认，采集恢复 |
| 数据质量 | 检查摘要有效位、年龄及新采集时间 | 时间可信与字段有效分别判断，不把校时当成通讯修复 |
| 异常处理 | 若未确认，记录诊断原因和core日志 | RTC/记录异常要保留提示，不能修改开关消除 |

~~~sh
# 重启采集及网页服务，用于先验证进程重启恢复。
sh /home/level-gateway/current/deploy/service.sh restart

# 等待启动检查及首次采集；RTC走时检查本身约1.1秒。
sleep 5

# 查看启动的时间检查结果，正常应含clock trusted=true source=rtc。
tail -n 20 /home/level-gateway/logs/core.log

# 确认核心服务健康；此项不代替RTC断电保持及数据采集验收。
/home/level-gateway/current/bin/gateway-core --health-check --ipc unix:/home/level-gateway/data/core.sock
~~~

## 6 自动确认的条件和边界

- 记录采用原子替换、文件同步及目录同步保存；校时前先写失效记录，避免中途断电继续沿用旧认证。
- 记录必须是本程序支持的格式，RTC路径与上次保存一致，且上次RTC保存成功、记录未失效。
- RTC日期须在2020～2100年内；驱动支持失效标志时，有告警不恢复可信。
- 开机间隔约1.1秒读取两次，RTC须正常前进1～3秒，避免停走时钟仅因日期合理而被接受。
- RTC不得早于最近可信检查点超过2秒，距检查点超过366天也要求重新校核。最近可信时间每分钟保存一次，正常退出再保存；不能据此检测所有小幅漂移。
- 系统时间与RTC相差超过2秒时，只有启用ALLOW_CLOCK_SET才能自动恢复系统时间；恢复完成后再打开数据库、串口及北向服务。
- 运行中发现系统日历时间相对单调时钟跳变超过2秒，撤销当前及缓存时间信任，并持久记录失效，等待重新校核。
- 模拟模式不访问RTC、不修改电脑系统时间，也不从真实设备记录恢复信任。

本次未新增自动NTP客户端或修改现场网络；没有网络也可通过已校准且正常工作的RTC恢复。RTC属于保持走时来源，不能代替精确时间服务器。程序不更改设备时区，也不追认校时前的旧样本或历史记录。
