# 设备永久授权与厂家发放说明

适用：软件0.8.0起；当前软件0.8.3／安装包0.8.3-20261117-r1。授权不占用Modbus寄存器，客户仍使用V3.2-D2通讯。本文属于产品实施说明，与开发协议分开保存。

## 1 使用方式

一台网关一份永久授权，不需要联网激活或按年续费。厂家交付前完成授权，客户正常使用时不需要操作。

换IP、改管理员密码、校时、重启、断电或正常升级，不改变本机授权。更换主板或用于识别的板载存储器后，需要厂家为新硬件重新签发。把程序、配置和授权一起复制到另一台网关，硬件编号不一致，无法启用采集、控制与北向服务。

| 网页提示 | 含义与操作 |
| --- | --- |
| 本机永久授权已生效 | 正常使用，没有到期时间。 |
| 尚未安装／授权不匹配／签名失败 | 只开放管理网页。下载申请文件，向厂家申请本机授权；不采集、不控制、不提供Modbus TCP/RTU服务，不保存虚假的测量历史。SYS3表示异常。 |
| 永久授权已保存，重启后开始采集 | 文件校验并保存成功。安排维护窗口，人工点击“重启网关程序”，再次登录核对授权和读数。导入本身不自动启动采集。 |
| 本次运行已通过，但保存的文件异常 | 当前进程继续运行。重启前重新导入厂家原授权文件，避免重启后进入未授权状态。 |
| 模拟运行 | 电脑演示使用模拟仪表，不访问实际串口，不是实机授权。 |

授权不会替代现场控制许可。真实写入仍须硬件写开关、对应TCP/RTU写许可及动作白名单全部满足；状态4/5仍按原流程人工核查并复位，授权导入与重启不重发仪表动作。

## 2 网页申请与导入

1. 登录管理网页，进入“系统维护→设备永久授权”，点击“下载本机申请文件”。将`.gwreq`文件发给厂家。申请文件是硬件编号的摘要，不包含管理员密码或厂家私钥。
2. 厂家签发该设备的`.gwlic`永久授权文件。登录同一台网关，选择文件，勾选来源确认，点“校验并保存授权”。
3. 核对网页显示的设备码、客户名称及授权编号。安排维护窗口，使用本页“重启网关程序”，不需要重启整个Linux系统。
4. 重新登录，确认“本机永久授权已生效”，检查采集读数和上位机通讯。授权文件不能用于另一台设备。

网页导入须管理员登录、同源校验、请求校验及人工确认。文件最大8KiB；设备核验厂家签名、产品、永久属性、硬件类型和设备码。导入事件记录来源、授权编号和设备码；不会记录私钥。

## 3 从0.7及更早版本首次升级

**0.6.0 样机可全程在网页办理。** 在原网页先安装 0.7.0-20261109-r2 过渡包，再下载本机申请。厂家按第 4 节签发，客户在过渡网页校验并保存授权后直接安装 0.8.1，无需中途重启。全过程见[网页升级说明第 1 节](29_网页上传升级操作说明.md)。过渡包沿用已发布的 0.7 采集核心，等待授权期间按原配置工作。正式版启动时重新验证保存在 config/license.json 的永久授权。

**厂家也可以在旧版运行时通过终端完成预授权。** 以下为终端操作。

在电脑保留原版本、设备配置及历史备份，将新ARM64安装包上传到`/tmp`，按说明10校验、解压。以下命令在网关SSH／Console终端执行，只读硬件编号，不访问串口、不停止现有采集。实际目录以本次包为准。

~~~sh
# 指定已校验、解压的新包目录；此时尚未切换正在运行的旧程序。
gateway_new_pkg=/tmp/gt6757s-0.8.3-20261117-r1-linux-arm64
# 为新包中的核心程序设置执行权限。
chmod 755 "$gateway_new_pkg/bin/gateway-core"
# 导出本机申请到临时目录；已有文件不会覆盖，申请完成后程序退出。
"$gateway_new_pkg/bin/gateway-core" --license-request /tmp/gateway.gwreq
~~~

把`/tmp/gateway.gwreq`下载到厂家电脑，按第4节签发，再把该设备授权文件上传为`/tmp/gateway.gwlic`。在网关继续执行：

~~~sh
# 用新程序对上传文件检查厂家签名和本台硬件；成功后才进行下一条命令。
"$gateway_new_pkg/bin/gateway-core" --check-license --license-file /tmp/gateway.gwlic
# 备好授权保存目录，不改已有仪表配置与数据库。
mkdir -p /home/level-gateway/config
# 将已校验的本机授权保存到固定配置目录；首次预授权使用，已有授权应先备份。
cp /tmp/gateway.gwlic /home/level-gateway/config/license.json
# 限制授权文件的本机读取权限；文件只含签名，不含厂家私钥。
chmod 600 /home/level-gateway/config/license.json
# 再从实际保存位置检查一次，确认升级后能读取正确授权。
"$gateway_new_pkg/bin/gateway-core" --check-license --license-file /home/level-gateway/config/license.json
~~~

随后才使用原网页上传本次`.gwup`，或运行说明10的手动安装／向导。手动安装器对已有部署在停服前检查授权，未通过则退出，旧程序继续运行。网页升级的目标启动检查包含授权门槛；缺失或不匹配时不会报告升级成功，会按兼容恢复流程恢复原版本。

新机可以先安装并初始化管理员，管理网页正常启动，但未授权时不会开启采集。按第2节导入后人工重启程序即可。首次验收还须完成第7节的板端检查。

## 4 厂家电脑签发

仅厂家电脑保存`private/license-signing.key`及发放工具`output/windows-amd64/gateway-license.exe`。密钥已在本项目建立，**不要再次生成或用其他密钥替换**。授权公钥编译在核心程序内，不允许客户通过网页替换。

授权签发密钥与网页升级签名密钥是两套独立密钥。二者均须在厂家受控位置另做离线备份；保留原密钥才能持续支持已交付设备。不要把`private`目录、签发工具或源程序放入客户运行包。

在厂家电脑打开PowerShell，进入“设备采集网关”项目目录，先把客户申请文件保存到`private/requests/gateway.gwreq`，按实际客户名及设备编号修改下列参数。每次使用新的输出文件名，不覆盖原文件。

~~~powershell
# 为申请文件对应的单台设备签发永久授权，记录客户名称，并自动追加厂家签发台账。
& ./output/windows-amd64/gateway-license.exe issue --request ./private/requests/gateway.gwreq --customer '重庆耐德东京计装仪表有限公司' --output ./private/licenses/gateway-001.gwlic
# 在厂家电脑核对该文件的签名及客户记录；设备本机还会再次核对实际硬件编号。
& ./output/windows-amd64/gateway-license.exe verify --input ./private/licenses/gateway-001.gwlic --public-key ./src/internal/licensing/trusted-public.json
~~~

将输出`.gwlic`发给对应设备的安装人员。`private/license-issued.jsonl`保存设备码、客户、授权编号和签发时间，签发完成应与合同设备编号对应登记。核对命令不显示私钥。

## 5 程序和文件

| 文件／机制 | 说明 |
| --- | --- |
| `config/license.json` | 实机永久授权，独立于发布目录；升级保留，不放入通用安装包。 |
| `.gwreq` | 本机申请文件；硬件类型及摘要，不带原始CPU／eMMC编号。 |
| `.gwlic` | 厂家签发文件；Ed25519签名保护产品、设备、客户及永久属性。 |
| 核心程序内置公钥 | 只用于验签，不可用于签发新授权；不接受设备侧自建信任公钥。 |
| `private/license-signing.key` | 厂家授权私钥，不部署、不对客户提供；与升级签名密钥分开。 |
| `private/license-issued.jsonl` | 厂家签发台账，不部署设备。 |

优先读取SoC序列号，其次CPU Serial，再使用板载eMMC CID。只接受系统确认类型为MMC的`mmcblk0`，不绑定可移动SD卡。已授权设备按授权文件中的硬件类型继续核对，后续系统增加其他编号接口不会自行换码。不使用IP、MAC地址、主机名或可随文件系统复制的machine-id。

授权按每次核心程序启动核验，运行中不因时钟、联网或授权文件临时损坏突然停采。保存文件异常会在网页提示，须在下次重启前处理。该机制防止直接复制后正常使用；取得root并修改二进制或安装历史无授权程序仍可能绕过，不能承诺无法破解。现阶段不改厂家加密芯片密钥，不设置不可恢复的芯片口令。

## 6 升级、备份和恢复

手动安装对已有配置只补缺失项，保存`license.before-发布标签.json`副本；网页升级保留实际`config/license.json`，新执行器还将它纳入升级备份。旧0.7执行器首次切换0.8时尚未备份授权，但不会删除或覆盖预先保存的原授权文件。应用回退不会拿另一台设备的授权替换本机授权。

重装同一硬件时可导入厂家原文件。设备损坏换板时重新导出申请，由厂家核对采购及原设备记录后签发；旧授权不会因此自动联网撤销。授权永久，不能依赖改系统时间实现失效控制。

## 7 检查与上板验收

本机应检查：签名篡改、其他设备复制、无文件、坏文件、未取得稳定编号均不能开启采集／控制／北向；导入后须重启；永久授权不依赖当前日期；换IP和升级继续使用原文件；导入来源有记录；运行包仍为16文件且不含源码、文档和私钥。

**真实GT6757S上尚须验收**：读取实际硬件类型与设备码，重启及断电后码不变；本机授权正常采集；复制到另一块板不能采集；由0.7预授权升级、错误授权恢复、网络修改及重启后授权保留。电脑模拟通过不等于上述板端通过。未读到稳定编号时先联系厂家核查，不用MAC或固定字符串代替。

0.8.0正常升级到0.8.1时保留原永久授权，不重复申请。0.6.0 或 0.7.0 首次进入授权版，可按第 3 节选网页过渡或厂家终端预授权。
