## 1 使用范围

先在PowerShell进入设备采集网关项目目录。演示只需第2、3节；上位机读取练习见第5节；第6节仅供开发电脑构建和整理客户资料，不是上板前必须执行的步骤。

## 2 电脑环境与pwsh问题

**电脑执行；本节先完成，再执行后续电脑命令。**

### 2.1 进入项目目录

~~~powershell
# 设置实际网关项目目录；项目移动时修改此路径。
$gatewayRoot = 'E:/Works/耐得/耐德东京计装/液位管理系统_20260704/设备采集网关'

# 进入该目录；-LiteralPath按原样处理中文和空格。
Set-Location -LiteralPath $gatewayRoot

# 确认当前目录以“设备采集网关”结尾。
Get-Location
~~~

### 2.2 找到PowerShell 7

脚本要求PowerShell7.0以上。pwsh是PowerShell7程序名；powershell.exe通常是Windows自带5.1。仅看“PS”提示符不能判断版本。

“无法将pwsh识别为cmdlet…”说明程序不在当前PATH中，脚本尚未运行。以下先查PATH，再查常见位置。找到后用gatewayPS7变量调用，打开新终端后重新设置。

~~~powershell
# 查询PATH中的pwsh程序；未找到时返回空。
$gatewayPS7 = (Get-Command pwsh -ErrorAction SilentlyContinue).Source

# PATH找不到时，检查普通安装位置和本机Codex配套运行时。
if (-not $gatewayPS7) {
    # 第二项仅适用于装有相应Codex运行时的电脑。
    $gatewayPS7Candidates = @(
        "$env:ProgramFiles/PowerShell/7/pwsh.exe"
        "$env:USERPROFILE/.cache/codex-runtimes/codex-primary-runtime/dependencies/native/powershell/pwsh.exe"
    )
    # 选择第一个存在的程序文件，不修改系统PATH。
    $gatewayPS7 = $gatewayPS7Candidates | Where-Object { Test-Path -LiteralPath $_ } | Select-Object -First 1
}

# 没找到则停止；安装PowerShell7或填写其实际完整路径后继续。
if (-not $gatewayPS7) { throw '未找到PowerShell7，请安装或指定pwsh.exe完整路径。' }

# 显示实际选择的执行器路径。
$gatewayPS7

# 检查版本；&调用变量中的程序，-NoProfile不加载个人启动配置。
& $gatewayPS7 -NoLogo -NoProfile -Command '$PSVersionTable.PSVersion.ToString()'
~~~

本机2026-10-14查到配套执行器版本7.6.5。缓存路径可能随运行时更新改变，长期维护电脑宜正常安装PowerShell7。不能把命令简单改成powershell.exe来执行要求7.0的脚本。

### 2.3 按任务准备工具

| 任务 | 所需工具 |
| --- | --- |
| 用现有exe演示 | PowerShell7、浏览器 |
| 使用TCP调试工具 | Python3，调试工具只用标准库 |
| 设备登录和上传 | SSH/SFTP工具 |
| 源码构建 | PowerShell7、Go、Node.js、npm及项目依赖 |
| 客户PDF生成 | Python及生成器需要的库 |
| 板端运行 | 对应架构的编译包；不需要在板端安装Go、Node.js、Python |

~~~powershell
# 优先选择本机配套Python，该环境已核对有PDF依赖。
$gatewayPython = "$env:USERPROFILE/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe"

# 没有配套环境时，改用PATH中的Python3。
if (-not (Test-Path -LiteralPath $gatewayPython)) {
    # 取得实际Python程序路径，后续还要检查版本与所需库。
    $gatewayPython = (Get-Command python -ErrorAction SilentlyContinue).Source
}

# 检查Python版本；应为Python3，无法运行时先修正gatewayPython。
& $gatewayPython --version

# 检查SSH登录工具是否存在；此处不建立连接。
Get-Command ssh -ErrorAction SilentlyContinue

# 检查SCP上传工具是否存在；没有时使用现有SFTP软件。
Get-Command scp -ErrorAction SilentlyContinue
~~~

## 3 本机演示

**电脑执行，设备采集网关目录；已完成第2节。** 演示不打开真实UART或LED，不修改电脑时钟。

### 3.1 检查文件并启动

~~~powershell
# 检查采集核心exe；False时先按第6节构建。
Test-Path -LiteralPath './output/windows-amd64/gateway-core.exe'

# 检查网页exe；也必须存在。
Test-Path -LiteralPath './output/windows-amd64/gateway-web.exe'

# 启动32台模拟仪表；-File指定脚本，-Meters是模拟台数，允许1～64。
& $gatewayPS7 -NoProfile -File ./tools/start-demo.ps1 -Meters 32
~~~

成功后后台运行core、web，终端显示访问地址。若“Demo already running”，先按3.4停止旧演示，不重复启动另一套。

| 演示项目 | 值及说明 |
| --- | --- |
| 网页 | http://127.0.0.1:8088 |
| Modbus TCP | 127.0.0.1:1502，Unit ID1 |
| 内部API | 127.0.0.1:19090，仅本机core/web使用 |
| 首次密码 | output/demo/login-password.txt，本机文本编辑器查看 |
| 账号 | output/demo/admin.json，已存在时不重新生成 |
| 数据库 | output/demo/gateway-v2.db，停止后保留 |

127.0.0.1是本机回环地址，其他电脑或平板不能通过它连接此演示。

### 3.2 登录和观察

浏览器输入上述网页地址，用login-password.txt中的密码登录。密码仅本机查看，不放入日志、聊天或客户资料。

“当前数据”核对模拟台数和数据年龄；“历史与诊断”核对version=0.7.0、map_version=3，页眉应显示模拟运行。网页每2秒刷新，与默认3秒采集目标不同。

### 3.3 查看日志与端口

~~~powershell
# 检查网页端口是否可连接；TcpTestSucceeded=True表示建立连接成功。
Test-NetConnection 127.0.0.1 -Port 8088

# 检查模拟TCP端口；这一步还没有验证寄存器内容。
Test-NetConnection 127.0.0.1 -Port 1502

# 查看核心最近40行日志；Go运行日志通常写到stderr文件。
Get-Content -LiteralPath './output/demo/core.err.log' -Tail 40

# 查看网页最近40行日志。
Get-Content -LiteralPath './output/demo/web.err.log' -Tail 40
~~~

端口占用、配置或数据库错误先按日志定位。端口连通后按第5节核对实际寄存器。

### 3.4 停止或改变模拟台数

~~~powershell
# 停止脚本记录的web/core进程；核对PID和程序路径，不停止无关进程。
& $gatewayPS7 -NoProfile -File ./tools/stop-demo.ps1
~~~

停止保留账号、配置、库和日志。再次start-demo会重新生成config.json，网页更改可能被重置，但数据库不清空。

若要演示8台，在停止后执行：

~~~powershell
# 重新生成8台演示配置并启动；只影响本机演示配置。
& $gatewayPS7 -NoProfile -File ./tools/start-demo.ps1 -Meters 8
~~~

## 4 网页配置参数

### 4.1 采集、TCP与历史

| 参数 | 默认/演示值 | 含义及设置方法 |
| --- | --- | --- |
| 运行模式 | 正常采集 | 轮询南向仪表；维护模式暂停采集，旧数据会逐渐过期 |
| 快速周期ms | 3000 | 常用液位、温度/状态、密度/状态组目标间隔，约3秒。每口串行、不同口并行，实际受台数、波特率、超时和动作插入影响 |
| 详情周期ms | 30000 | 启用的温度/密度/模拟量详情组目标间隔，约30秒，降低总线负担 |
| TCP服务端口 | 演示1502；实机502 | 网页只修改端口，保留现有接入IP；实机在系统维护选择接入网口，下方只读显示访问地址。演示初始IP由启动配置确定 |
| TCP站号 | 1 | 请求中的Unit ID，范围1～247。各仪表同一Unit ID，编号由寄存器地址区分 |
| TCP并发连接 | 8 | 同时连接客户端上限，1～16；不是液位计数量 |
| 启用Modbus TCP | 开启 | 打开TCP入口。四口全南向时客户通过TCP访问 |
| 允许TCP提交命令 | 生产关闭、演示开启 | 控制写入口许可；关闭仍可读测量数据 |
| 历史周期秒 | 60 | 每分钟保存各仪表当时的缓存快照，不是采集周期 |
| 历史保留天 | 30 | 按时间清理旧历史；系统时间未确认时暂停按日期清理 |
| 历史容量MiB | 256 | 按数据库占用清理较早历史，可能使实际保留短于30天。1MiB=1024×1024字节 |

快速周期1000～60000ms；详情周期不小于快速周期且不超过3600000ms。历史周期1～86400秒、保留1～365天、容量16～2048MiB。超范围保存被拒绝。

参数区另有约10分钟周期，并非所有寄存器都随详情周期刷新。

默认有效窗口=快速周期×3=3000×3=9000ms。某组距离最后成功采集超过9秒时，对应有效位清0；一次失败但旧值仍在窗口内时可能保持有效，同时有采集警告。分别查看valid、quality和年龄。

### 4.2 四个485口与仪表绑定

| 配置项 | 说明 |
| --- | --- |
| 南向采集 | 网关作为RTU主站；每口最多16台 |
| 北向RTU | 网关作为RTU从站供上位机读取，该口不挂南向液位计 |
| 停用 | 本应用不使用此口 |
| 串口参数 | 与仪表实际值一致。FW南向支持1200/2400/4800/9600、8E1，常用4800 |
| 超时ms | 单次通讯等待限制，50～5000ms；首次可500ms，后续实测调整 |
| 北向站号/写许可 | 只作用于该北向RTU口；TCP另有自己的站号和写许可 |
| 仪表编号/槽位 | 决定客户读取的网关寄存器位置 |
| 仪表站地址 | 液位计自身南向地址，1～243；同一COM不重复，不同COM可重复 |
| 温度/密度详情 | 是否轮询相应低频详情组，不负责启动测量 |

正常模式至少两路南向。首次一台可设COM1/COM2均南向，仅COM1绑定一台，COM2空口不轮询仪表。

| 规模 | COM1 | COM2 | COM3 | COM4 | 北向 |
| --- | --- | --- | --- | --- | --- |
| 32台 | 南向16 | 南向16 | 北向RTU | 停用 | TCP＋RTU |
| 48台 | 南向16 | 南向16 | 南向16 | 北向RTU | TCP＋RTU |
| 64台 | 南向16 | 南向16 | 南向16 | 南向16 | TCP |

角色可置换。编号1～16等按COM分组只是推荐分配；实际采集按绑定进行。

### 4.3 动作白名单

勾选只允许提交该动作，不会立即执行。真实控制还需TCP/RTU入口许可和启动硬件写开关。

| 北向指令值 | 动作 |
| ---: | --- |
| 1 | 测量Ⅰ |
| 2 | 测量Ⅱ（界面） |
| 3 | 测量Ⅲ（罐底），与7保留独立命令编号 |
| 4 | 停止；独立停止入口也要许可此动作 |
| 5 / 6 | 上升 / 下降 |
| 7 | 远程密度；与本地按钮启动所得密度是同一工艺数据，区别在启动方式 |
| 9 / 10 | 重复性检查 / 液体震荡回避，FW扩展，按仪表支持与现场许可开通 |

北向编号由网关转换成南向HR699动作位。生产不要直接照搬演示的全勾选配置。

### 4.4 保存

点击“保存并应用配置”，等待成功提示，再核对绑定、读数、年龄。端口/模式/周期变更可能重建相关运行通道。

任何正常或独立停止周期非空闲时，有变更配置会被拒绝。先按D2记录结果和处理周期，不删除数据库解锁。修改前导出配置留存。

## 5 Modbus TCP调试

**电脑执行，已设置gatewayPython。** 工具采用零基地址，--host、--port、--unit是全局参数，放在read/status等子命令前。

### 5.1 本机只读检查

~~~powershell
# FC04读地址0起30字，查看网关原始信息。
& $gatewayPython ./tools/modbus_client.py read 0 30

# 地址2起2字预期[3,64]：协议版本3、最大64槽位。
& $gatewayPython ./tools/modbus_client.py read 2 2

# 地址27起3字预期[8,3,12]：单口上限8、D2能力3、控制步长12。
& $gatewayPython ./tools/modbus_client.py read 27 3

# 四次96字读取解析64槽位批量数据；无效字段输出null。
& $gatewayPython ./tools/modbus_client.py batch

# 按每台24字摘要解析32台，工具自动按最多5台分批。
& $gatewayPython ./tools/modbus_client.py summary --meters 32

# 读取编号1原始摘要，1000是零基地址，24是寄存器字数。
& $gatewayPython ./tools/modbus_client.py read 1000 24

# FC03查询编号1正常/停止周期，只查询不动作。
& $gatewayPython ./tools/modbus_client.py status --slot 1
~~~

编号n摘要起址=1000＋24×(n－1)，控制起址C=30000＋12×(n－1)。全部同一网关Unit ID，仪表编号不填成Unit ID。

### 5.2 读取真实设备

示例设备IP192.168.0.230、端口502、Unit ID1，使用前换成实际交付值。

~~~powershell
# 检查电脑到设备502端口，尚未验证Modbus内容。
Test-NetConnection 192.168.0.230 -Port 502

# FC04读取真实设备版本及容量，预期[3,64]。
& $gatewayPython ./tools/modbus_client.py --host 192.168.0.230 --port 502 --unit 1 read 2 2

# 读取D2能力和控制步长，预期[3,12]，不代表已开真实写许可。
& $gatewayPython ./tools/modbus_client.py --host 192.168.0.230 --port 502 --unit 1 read 28 2

# 首次读取编号1的换算摘要。
& $gatewayPython ./tools/modbus_client.py --host 192.168.0.230 --port 502 --unit 1 summary --meters 1

# 查询编号1完整控制状态，不提交动作。
& $gatewayPython ./tools/modbus_client.py --host 192.168.0.230 --port 502 --unit 1 status --slot 1

# 直接读取30000起12字控制块必须FC03；--fc 3覆盖read默认FC04。
& $gatewayPython ./tools/modbus_client.py --host 192.168.0.230 --port 502 --unit 1 read 30000 12 --fc 3
~~~

### 5.3 在本机模拟环境练习动作

**下列会提交动作，先只用于本机模拟。真实设备另按第11节和厂家现场许可执行。** 不把所有代码块一次粘贴运行，先看状态再选下一步。

~~~powershell
# 先确认正常指令/state及stop_request/stop_state均为0；否则先处理原周期。
& $gatewayPython ./tools/modbus_client.py status --slot 1
~~~

~~~powershell
# 提交编号1“上升”；--slot是网关编号，--command 5是北向动作编号。
& $gatewayPython ./tools/modbus_client.py action --slot 1 --command 5

# 查询状态和错误；写应答仅表示网关受理。
& $gatewayPython ./tools/modbus_client.py status --slot 1
~~~

| state | 含义及下一步 |
| ---: | --- |
| 0 | 空闲，可开始新周期 |
| 1 / 2 | 受理排队 / 执行，继续查询 |
| 3 | 指令回读确认，记录结果；物理完成另行判断 |
| 4 | 失败或取消，查看error |
| 5 | 不确定，厂家现场核查，客户不能直接清零或自动重发 |

需要浮子停止：

~~~powershell
# 独立停止向C+7写1，正常周期忙时也可走该入口。
& $gatewayPython ./tools/modbus_client.py stop --slot 1

# 查询stop_state/stop_error和原正常状态；停止确认不消除原未知。
& $gatewayPython ./tools/modbus_client.py status --slot 1
~~~

到状态0/3/4并记录结果，或状态5已完成人工现场核查且留档后，再分别清相应周期：

~~~powershell
# 正常周期允许复位时向C+0写0；这不是浮子停止。
& $gatewayPython ./tools/modbus_client.py reset --slot 1
~~~

~~~powershell
# 独立停止周期允许复位时向C+7写0；--stop选择停止周期。
& $gatewayPython ./tools/modbus_client.py reset --slot 1 --stop
~~~

工具不自动重试、清零或重放。掉应答先查status；每台只有一个控制方，前一周期动作和复位重试在新周期前结束。状态3不能作为浮子到位、密度或平均测温任务完成判据。

## 6 开发电脑构建与打包

**电脑执行，设备采集网关目录。已有运行包的安装人员可跳过本节。**

### 6.1 构建程序

当前go.mod要求Go1.27.0。build.ps1优先使用.build-tools/go/bin/go.exe，否则查PATH中的go，并设GOTOOLCHAIN=local，不自动选择其他工具链。网页依赖按锁文件安装。

~~~powershell
# 查看项目Go版本和依赖声明。
Get-Content -LiteralPath './go.mod' -TotalCount 8

# 检查Node.js是否可运行。
node --version

# 检查Windows构建脚本使用的npm.cmd。
npm.cmd --version

# 按package-lock.json安装网页依赖；--prefix指定网页项目，需网络或完整缓存。
npm.cmd ci --prefix ./src/web

# 从north-v3.json生成V3点表和动作映射，校验D2合同。
& $gatewayPython ./tools/generate_v3_map.py

# 完整构建：网页编译、Go fmt/vet/test，再编译Windows、ARM64、ARMv7。
& $gatewayPS7 -NoProfile -File ./tools/build.ps1

# 生成并校验16/24/32/48/64台生产模板和演示模板；不修改设备现场配置。
& $gatewayPS7 -NoProfile -File ./tools/generate_configs.ps1
~~~

发布采用默认完整构建，不通过-SkipTests/-SkipWeb跳过步骤。首次依赖缓存不全时需可用依赖来源；板端只运行编译文件。

| 结果 | 位置 |
| --- | --- |
