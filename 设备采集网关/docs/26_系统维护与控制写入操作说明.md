## 1 修改网页管理员密码

登录网页，打开“系统维护→修改管理员密码”。依次输入原管理员密码、新管理员密码、再次输入新密码，点击“保存新密码并退出登录”。新密码为12～128个ASCII字符，无首尾空格，两次一致，不能与原密码相同。

成功后所有已登录电脑、手机和平板会话失效，需要重新登录。采集核心、Modbus服务、仪表采集及配置不因此重启。失败时按页面提示处理，不要把密码粘贴到诊断记录中。原密码连续错误达到限额后暂时限制修改请求，稍后再试。

admin.json保存随机salt、PBKDF2-SHA256校验hash和迭代次数，不含明文密码。网页自动原子替换此文件并更新当前服务的校验信息，不需要手工编辑，也不需要重启程序。升级保留新密码，程序重启后继续使用；它与Linux root密码、Modbus入口许可无关。

程序先登记密码变更准备事件，再保存新凭据并注销所有会话，最后登记完成事件。若准备事件无法保存，拒绝变更；若文件已经替换但目录同步或完成登记失败，页面明确提示“新密码已生效”及维护警告，不声称仍使用旧密码。近期事件admin_password_change_prepared/admin_password_changed/admin_password_change_failed记录关联ID、时间和来源，不记录密码、盐或校验hash。准备与完成分两次登记，不冒充跨文件和数据库的单事务。

忘记原密码仍由厂家在设备终端核查恢复，没有免认证的网页重置入口。不要删除数据库或覆盖整份配置。首次安装初始化密码仍按[部署10第5章](10_运行部署与维护.md)执行。

## 2 重启网关程序

打开“系统维护→重启网关程序”，先处理未保存的配置，再核对现场状态，勾选“我已确认现场状态，知晓通讯将中断，重启不等于停止浮子”，点击“确认重启网关程序”。程序不会把勾选当成停止指令，也不替人判断浮子是否处于安全位置。

| 情况 | 程序处理 |
| --- | --- |
| 正常动作或独立停止为状态1/2 | 拒绝网页重启，先处理当前控制。 |
| 存在状态3/4/5 | 允许按现场确认操作重启，原状态和记录保留；状态5不自动解除。 |
| 存储或控制恢复异常 | 拒绝网页重启，先检查诊断及设备终端。 |
| 重复提交正在受理的重启 | 返回同一任务ID，不再启动一份任务。 |
| 重启已受理、旧核心尚未退出 | 临时拒绝新的北向控制/复位、配置修改、网页校时和人工复位；测量读取暂时继续。 |
| 独立任务启动/执行失败、旧程序还在运行 | 解除重启临时拦截，显示错误并留事件，不自动循环重试。 |

后台独立任务在响应返回后安排服务重启，正常停止网页和采集核心，再启动两者。服务正常退出时等待采集任务结束、关闭存储并保存必要时钟记录；不会强行杀掉仍未正常停止的服务后继续启动一套。期间采集、网页和Modbus通讯短暂中断，数据缓存重新采集，配置、密码、历史及控制记录保留。**Linux不重启，浮子不因此停止，动作不自动重发。**

页面显示等待重连，约每2秒尝试连接，最长约120秒；网页恢复后提示重新登录，登录后核对运行时间、采集更新及控制记录。恢复提示只说明网页能连接，不代替采集或机械状态验收。超时或失败时检查服务日志，不连续点击或自动重发。

网页重启仅在受控服务启动时提供：本台Buildroot使用新deploy/supervise.sh自动传入固定service.sh路径。电脑普通演示、直接启动二进制或未适配的systemd服务会显示未启用，此时按钮不可用。不能通过网页指定脚本、Shell命令、系统重启或关机参数。systemd固件须按自身服务管理方式维护，不能混用当前Buildroot监督脚本。

设备终端的手动维护路线仍保留，先核对没有执行中控制：

~~~sh
# 正常重启应用服务；这是人工维护命令，不重启Linux系统。
sh /home/level-gateway/current/deploy/service.sh restart

# 查看两个服务监督器的状态，不据此单独认定采集有效。
sh /home/level-gateway/current/deploy/service.sh status

# 检查采集核心调度，预期healthy；仍须在网页核对实际读数。
/home/level-gateway/current/bin/gateway-core --health-check --ipc unix:/home/level-gateway/data/core.sock

# 查看独立重启任务日志，失败时不自动重试。
tail -n 50 /home/level-gateway/logs/maintenance.log
~~~

网页重启受理事件为program_restart_requested，包含任务ID、来源、时间和旧boot标识；启动/执行失败记录program_restart_failed。正常重启后的新boot和运行时间用于核对程序确实重新启动。

## 3 允许客户写控制：完整开通步骤

权限只开放D2规定的动作/复位寄存器，不开放任意液位计寄存器写入或缓存自动下发。三项权限分工如下：

| 条件 | 设置位置 | 中文说明 |
| --- | --- | --- |
| 真实动作总开关 | service.env：HARDWARE_WRITES=1 | 启动时读取，修改后必须重启程序。默认0，只读采集。 |
| 入口写许可 | TCP的“允许TCP提交命令”；或对应北向RTU口的“北向写许可” | 分入口控制，不必把所有入口都开通。读取不受写许可关闭影响；入口许可关闭时该入口不能提交动作或复位。 |
| 允许动作清单 | “允许的仪表动作” | 只勾选现场核准动作；独立停止也必须勾选“停止”。 |

以下步骤由厂家按现场许可操作，先保持客户上位机不自动发送控制。

1. 确认唯一控制方、浮子现场状态、实际罐号/槽位绑定、液位计站址及串口参数。运行模式选择“正常采集”，仪表已启用且绑定南向口。
2. 先处理原控制周期：状态3/4记录结果后复位；状态5必须人工核查后复位，禁止自动复位或自动重发。存在非空闲周期时，有变化的配置保存会被拒绝，不靠重启绕过。
3. 打开“端口与仪表”。使用TCP控制时勾选“启用Modbus TCP”和“允许TCP提交命令”；使用RTU时把对应口设为“北向RTU”，配置正确站号/串口参数并勾选该口“北向写许可”。32台四口全南向时只能用TCP；保留北向RTU口后最多24台。
4. 在“允许的仪表动作”勾选实际批准项目，并勾选“停止”，点击“保存并应用配置”。界面动作名对应客户动作编号，内部白名单是原FW南向动作位，不要直接拿白名单数字当客户命令。
5. 在设备终端备份service.env，并把硬件写入总开关改为1。下面每条成功后再继续，grep没有得到预期值时先用文本编辑器核对文件，不直接继续开通。

~~~sh
# 备份服务启动参数，保留原网口、时间及其他现场设置。
cp -p /home/level-gateway/config/service.env "/home/level-gateway/config/service.before-control-$(date -u +%Y%m%dT%H%M%SZ).env"

# 将已有真实动作总开关改为1，尚未重启时当前进程仍沿用旧值。
sed -i 's/^HARDWARE_WRITES=.*/HARDWARE_WRITES=1/' /home/level-gateway/config/service.env

# 确认文件中恰有预期HARDWARE_WRITES=1设置。
grep '^HARDWARE_WRITES=' /home/level-gateway/config/service.env

# 核对本轮不启用看门狗或HTTPS，这三项应保持空值。
grep -E '^(WATCHDOG|TLS_CERT|TLS_KEY)=' /home/level-gateway/config/service.env
~~~

6. 确认没有执行中控制后，使用“系统维护→重启网关程序”使启动参数生效；网页重启未启用时，选择本节提供的手动维护命令，不重复执行两种重启。
7. 重新登录，“历史与诊断→原始运行诊断”核对version=0.3.7、simulate=false、mode=normal、hardware_writes_enabled=true，control_error为空。再核对采集正常，才允许上位机进行人工控制试验。未接实机的电脑演示不能据此当成真实硬件控制验收。
8. 上位机按客户D2协议确认版本/能力/步长3/3/12，再提交已核准动作并读取状态。只在明确的新操作时写一次，不把周期轮询做成重复发动作。状态3仅代表指令回读确认，不证明机械动作完成。

电脑PowerShell只读核对示例，先按[电脑说明22](22_电脑演示构建与客户资料管理.md)设置gatewayPython；现场若TCP地址或站号不同，用实际值替换：

~~~powershell
# 读取协议版本和容量，预期[3,64]，不发送动作。
& $gatewayPython ./tools/modbus_client.py --host 192.168.0.230 --port 502 --unit 1 read 2 2

# 读取D2控制能力和步长，预期[3,12]，不发送动作。
& $gatewayPython ./tools/modbus_client.py --host 192.168.0.230 --port 502 --unit 1 read 28 2

# 查询槽位1的正常动作和独立停止状态，不发送动作。
& $gatewayPython ./tools/modbus_client.py --host 192.168.0.230 --port 502 --unit 1 status --slot 1
~~~

仪表1正常指令为30000、状态30001、错误30002；独立停止请求30007、状态30008、错误30009。地址均为零基PDU地址。向正常指令写0是复位，**不是停止**；独立停止提交值为1。动作编号、写入形状、人工复位和64台地址以[客户协议12](12_客户通讯协议V3.md)为准，此处不另造一套协议。

## 4 关闭控制、恢复只读

先在网页取消对应入口写许可并保存；需要保存配置而仍有非空闲控制时，先按D2处理周期。再在设备service.env中把HARDWARE_WRITES改回0，核对后无执行中控制时重启程序，确认hardware_writes_enabled=false。

关闭入口许可或总开关不会向液位计发送停止，不应作为紧急停止措施。管理员网页密码也不是Modbus密码；更改密码不会自动关闭或开启客户通讯入口。

## 5 本轮交付与验证边界

新包仍固定13个运行文件，网页资源内置，不上传用户文档、源码、测试或备用HTTPS根私钥。升级保留已有admin.json、配置、数据库和service.env，不重置密码、不自动开通硬件控制、HTTPS或看门狗。新增功能需现场升级后确认。

本机验证包含密码校验/持久化/会话注销、保存失败、审计、重启互锁与去重、独立任务、模拟服务恢复、旧控制保留及原有采集/控制回归。隔离测试只替换两个Windows测试进程，真实Buildroot正常退出、自启服务和手机访问另行板测。最终证据见[交付复核](../tests/system-maintenance-delivery-verification-20261019.json)。

软件0.4.1取消IR51 bit15控制拦截和回读限制；该位仍为原始模式信息。H129认证、故障检查和上述三层开通条件保留，最终接受以仪表应答和回读为准。旧版状态4/错误2不会因升级自动清除，可按现有流程写0复位后再提交新动作。

## 网页复位控制失败与不确定结果（0.4.2）

登录网页，进入“历史与诊断”，展开“控制失败与不确定结果复位”。页面列出全部64个槽位保留的状态4和5，包括未启用槽位及旧版本记录；正常动作与独立停止分别显示。状态4表示控制失败，状态5表示结果不确定，两者不能混为机械故障或已完成。

1. 查看仪表编号、原COM/站址、通道、指令、错误码、结果说明及是否可能已发送。
2. 状态4点击“复位失败结果”；状态5点击“核查并复位”，先核实现场状态。
3. 填写核查人员/工号、现场核查结果与复位原因（至少4字），勾选现场确认。
4. 点击“确认复位（不重发动作）”。成功后选中通道的指令/请求、状态和错误归零，累计次数保留，原记录及复位人员、原因、来源、时间写入审计。另一通道的结果保持。

全程只需要浏览器访问网关，无需连接Modbus TCP。复位不写南向H129或H699，不停止浮子，不自动重发；若需再次动作，须另行明确下发。状态1/2执行中及状态0/3不在本页面提供复位。周期已变更、已复位、未登录、缺少确认或保存失败会拒绝，不能用旧表单清除新的周期。

SYS3会因状态4或5保持常亮；复位所有相关结果且没有其他告警后才熄灭。只清一条记录，不保证消除其他告警。以往页面只筛选状态5，导致状态4虽使SYS3常亮，却显示“当前无需处理”；0.4.2已补齐。


## 远程液位修改许可

升级默认不开通。按本说明设置HARDWARE_WRITES=1并重启程序后，在“端口与仪表”勾选“远程液位修改（校准）”并保存。配置allowed_actions中增加512；它是网关许可，不是FW动作位。网页入口无需Modbus TCP连接或TCP写许可；客户Modbus入口仍分别要求TCP/北向RTU允许写。目标、提交、清认证、人工核查及结果复位见[说明28](28_远程液位修改与验收说明.md)。

## 网络设置

系统维护新增双网口配置，先读取原参数，再按说明31应用、通过新IP重新登录并人工确认。网络试用与改密码、程序重启、校时、控制和升级互斥。网页两个网口均可访问；不新增整机重启，WATCHDOG继续留空，默认HTTP。

软件0.8.3允许仪表有故障码时下发已开通的操作和独立停止，仪表自身判断是否执行。网关根据通讯应答及指令回读确认控制结果，故障字、质量告警和SYS3告警按实际情况继续显示。旧状态4／错误3保留，可经人工核查后复位，再提交新动作。
