## 1 经路由器Wi-Fi访问

接法：**网关维护网口 → 网线 → 路由器LAN口；手机 → 同一路由器Wi-Fi。** 不要求网关本身内置Wi-Fi，也不要求路由器连接互联网。

| 本台示例 | 设置或操作 |
| --- | --- |
| 网关维护口eth1 | 已知IP192.168.0.230/24 |
| 路由器LAN | 示例192.168.0.1/24，实际以路由器配置为准 |
| 手机Wi-Fi地址 | 应为192.168.0.x，且地址不与网关重复 |
| 网页监听 | service.env中WEB_LISTEN=192.168.0.230:8088 |
| 手机浏览器 | 输入完整地址http://192.168.0.230:8088，使用原管理员账号登录 |

如果路由器LAN是192.168.1.x，可以使用本台已知eth0地址192.168.1.230接LAN，新版项目服务的网页在两个IPv4网口监听原端口；要改变网口地址，进入“系统维护→网络设置”，不能只修改应用监听字段。选择接入网口时核对实际地址，两个网口继续按现场规划保持不同子网。

路由器“访客Wi-Fi”、无线隔离或“禁止访问局域网”可能阻止手机访问有线网关。应使用允许访问LAN的Wi-Fi。若电脑通过同一网口能访问、手机不能，先检查Wi-Fi地址、隔离规则、手机VPN/代理及是否误用了https地址。

只在实际更换网页监听IP时，在设备终端修改配置并重启；以现场已确认IP替换下面示例：

~~~sh
# 备份修改前的服务配置，保留现场设置。
cp /home/level-gateway/config/service.env "/home/level-gateway/config/service.before-wifi-$(date -u +%Y%m%dT%H%M%SZ).env"

# 本例改为设备已有的eth0地址；只有实际使用eth0接192.168.1.x局域网时才执行。
sed -i 's/^WEB_LISTEN=.*/WEB_LISTEN=192.168.1.230:8088/' /home/level-gateway/config/service.env

# 重启应用使监听地址生效，采集会短暂中断。
sh /home/level-gateway/current/deploy/service.sh restart
~~~

## 2 当前数据与详情

- 电脑宽屏保留表格；手机窄屏把每台仪表、每路COM和绑定参数显示为带字段名的卡片。表单单列排布，按钮和输入框适合触摸操作。
- 点击“查看”展开详情；同一行变为“收起”，详情标题旁另有“收起详情”。展开时自动滚动到详情区域。
- “复制详情”复制当前显示的完整JSON，并暂停详情自动刷新，便于粘贴给厂家分析。总览仍正常刷新，网关采集不停止；勾选“自动刷新详情”即可恢复。
- 详情给出中文组名、寄存器范围、最近成功时间、成功次数、累计失败次数、时间可信、质量字和有效字。累计失败次数成功后不清零。
- 普通HTTP局域网页面上，部分浏览器不开放新版剪贴板接口。页面会尝试兼容复制；仍不允许时显示选中的文本框，手机长按复制，电脑按Ctrl+C。不会把复制失败提示成成功。

复制兼容处理依据浏览器[Clipboard.writeText说明](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText)及[execCommand说明](https://developer.mozilla.org/en-US/docs/Web/API/Document/execCommand)；具体手机浏览器和剪贴板权限仍需实际验证。

## 3 控制失败与不确定结果如何复位

这是**控制失败（状态4）或控制结果不确定（状态5）**时的人工复位入口，不是日常读取数据必填项。旧版未发送的失败记录也会显示。例如：

1. 网关已发出上升指令，但液位计应答丢失，不能确认是否执行。
2. 网关在控制排队或执行期间断电；重启后保留原记录，按D2规则标为不确定，不自动重发。

程序锁存这项控制，避免上位机重复启动。获授权人员核对实际浮子和仪表状态后，在页面选择该记录，填写人员、原因并确认，才能解除锁存。**解除不停止浮子、不补发动作，也不证明机械动作已经完成。** 正常动作状态3只代表回读确认。

客户上位机也可在人工核查并记录人员、结果后，直接向原正常指令寄存器或独立停止请求寄存器写0，无需厂家到场或新增解锁地址。两条路径只复位所选通道，不相互解除；禁止自动复位、自动重发。Modbus方式的人员/结果记录在客户上位机，网页填写的核查记录在网关；网关均保存复位来源、时间、原控制及复位后状态。存储异常时先排除故障。

无状态4/5记录时显示“当前无需处理”，表格和填写表单不显示。存在记录时分别显示失败及不确定数量；状态4选择“复位失败结果”，状态5选择“核查并复位”，仪表、通道、状态及周期ID自动带入。期间若该周期已变更，表单会关闭，不能用旧记录解除新周期。运行存储异常时显示异常，不提供记录选择。

## 4 按液位计导出历史

1. 登录后打开“历史与诊断”。
2. 选择开始时间和结束时间，每次最多7天。
3. 在“液位计（槽位 / 名称）”选择，例如“槽位1 · 首台试验液位计”；选“全部液位计（全部槽位）”可导出全部。
4. 点击“导出CSV”，单台文件名含槽位编号。没有记录时仍生成列标题，不伪造数据。

选项同时显示槽位和名称，重名也能区分；停用和未配置槽位仍可选择，导出数据库中尚保留的历史。选择按槽位执行，不按同名仪表合并。页面刷新保持已选槽位，名称取已保存配置，不采用尚未保存的编辑内容。

CSV保留原15列，末尾增加“液位计名称”“名称说明”。名称是导出时当前配置名称，不是历史采集时名称；只有槽位和绑定版本都匹配才填写。更换仪表前的历史或已删除的配置不套用当前名称，名称留空并注明原因。导出包含所选槽位各绑定版本的记录，按“槽位＋绑定版本”区分历史仪表。

## 5 模拟量开关和四项读数

登录后进入“端口与仪表→仪表绑定”，为需要的液位计勾选“模拟量采集”，点击“保存并应用配置”；再回“当前数据”点击该台“查看”。手机上每项以带字段名的卡片显示，电脑显示表格。现有配置未启用时继续关闭，升级不会替厂家全部勾选。

| 显示项 | 原始字换算 | 单位与说明 |
| --- | --- | --- |
| IR27 | uint16÷1000 | mA，仪表模拟量输入第一项 |
| IR28 | uint16÷1000 | mA，仪表模拟量输入第二项 |
| IR29 | int16÷100 | %，仪表模拟量百分比第一项；先处理负数 |
| IR30 | int16÷100 | %，仪表模拟量百分比第二项；先处理负数 |

每行同时显示原始字和网关零基地址。仪表1为3027～3030，仪表n为3000+144×(n−1)+27～30。这四项来自液位计，不能当成网关计算的液位/量程百分比。

| 采集状态 | 如何看待数值 |
| --- | --- |
| 未启用 / 仪表停用 | 不采集，数值及原始字显示“—”。 |
| 等待首次采集 | 已启用但还没有成功样本，显示“—”。 |
| 采集失败，尚无成功数据 | 查看最近错误；显示“—”，不是0。 |
| 已采集 | 有成功样本且在参考窗口内；采集到真实0时正常显示0。 |
| 最近采集失败 | 如仍在窗口内，显示上次成功值并给出警告；不代表本轮成功。 |
| 数据已过期 | 上次成功样本已超过窗口；保留显示但标明旧值，不用作当前值。 |
| 寄存器不支持 | 本台仪表返回不支持，已有值标旧；无样本则“—”。确认支持后可关闭保存再开启保存重试。 |
| 维护模式，采集暂停 | 不继续轮询，有值标旧，无值显示“—”；恢复正常采集后等待更新。 |

参考窗口=3×已保存详情周期。默认详情30000ms，即30秒，窗口为90秒；不是快速数据默认9秒。实际周期受总线负载影响；页面显示的“目标周期”不承诺每台精确按此间隔到数。未保存的周期和开关不影响当前详情判断。开启模拟量会为每台启用仪表增加一组4字详情读取。

取消勾选并保存停止该组采集，重新开启先等待新样本，关闭前值不冒充新值。成功/失败计数在开关切换时保留，程序重启后运行计数重新累计。时间未确认与数值有效分开处理；数据年龄由网关计算，不用手机时间作过期判断。有效字127只说明快速字段，不覆盖模拟量。

“复制详情”包含四项数值、单位、状态及年龄，复制时这些内容与JSON一起暂停；勾选“自动刷新详情”恢复实时显示。

## 6 其余改进与检查

原始运行诊断、近期事件和命令结果可折叠，日常页面优先显示必要信息。配置有修改但未保存时给出提示，离开页面前浏览器会提示未保存变更；浏览器对该提示的支持范围以实际设备为准。

上线检查：手机横竖屏、查看/收起、复制及手动复制兜底、COM参数保存、历史导出及Wi-Fi断开重连。电脑尺寸模拟通过不代表真实手机、路由器及现场网段已经验收。网页功能升级后，旧浏览器必要时强制刷新再核对。

## 7 修改密码与重启程序

手机、平板和电脑均从“系统维护”进入。改密码输入原密码及两次新密码，保存后所有已登录终端退出；采集继续，不要求重启。新密码为12～128个ASCII字符，无首尾空格，不与原密码相同。

重启程序先处理未保存配置并确认现场，勾选中断影响提示后点击。正在执行的控制由服务器拒绝；接受后等待重连，不重复点击、不拔电。网页恢复后重新登录，核对运行时间、采集和控制记录。重启不停止浮子、不解除状态5、不重发动作，也不重启Linux；本轮不启用看门狗或HTTPS。详细维护及开通写控制见[26](26_系统维护与控制写入操作说明.md)。

## 网页复位控制失败与不确定结果（0.4.2）

登录网页，进入“历史与诊断”，展开“控制失败与不确定结果复位”。页面列出全部64个槽位保留的状态4和5，包括未启用槽位及旧版本记录；正常动作与独立停止分别显示。状态4表示控制失败，状态5表示结果不确定，两者不能混为机械故障或已完成。

1. 查看仪表编号、原COM/站址、通道、指令、错误码、结果说明及是否可能已发送。
2. 状态4点击“复位失败结果”；状态5点击“核查并复位”，先核实现场状态。
3. 填写核查人员/工号、现场核查结果与复位原因（至少4字），勾选现场确认。
4. 点击“确认复位（不重发动作）”。成功后选中通道的指令/请求、状态和错误归零，累计次数保留，原记录及复位人员、原因、来源、时间写入审计。另一通道的结果保持。

全程只需要浏览器访问网关，无需连接Modbus TCP。复位不写南向H129或H699，不停止浮子，不自动重发；若需再次动作，须另行明确下发。状态1/2执行中及状态0/3不在本页面提供复位。周期已变更、已复位、未登录、缺少确认或保存失败会拒绝，不能用旧表单清除新的周期。

SYS3会因状态4或5保持常亮；复位所有相关结果且没有其他告警后才熄灭。只清一条记录，不保证消除其他告警。以往页面只筛选状态5，导致状态4虽使SYS3常亮，却显示“当前无需处理”；0.4.2已补齐。
