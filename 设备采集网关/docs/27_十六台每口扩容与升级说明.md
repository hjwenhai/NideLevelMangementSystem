# 每口十六台扩容与升级说明

> 2026-10-29更新：软件0.5.0／V3.2-D2新增远程液位修改。网页“历史与诊断”可输入目标液位；上位机先向J=31000+4×(n−1)用FC10写目标高/低字，再向原C+0写11提交，沿用C+1状态和C+2错误。按FW9000NN资料实时读取IR0/1、HR503/504，用HR129=0xEA66认证，修改后清零认证；不向HR699写11或512。具体操作及板端验收见[远程液位修改说明28](28_远程液位修改与验收说明.md)。64台容量及原浮子动作不变。


2026-10-27。软件0.4.3，客户协议V3.1-D2，北向版本寄存器仍为3。每南向COM上限16台，整机64个稳定槽位。硬件仍为GT6757S，不增加物理串口。

## 连接容量

| 南向配置 | 仪表容量 | 北向方式 | 说明 |
| --- | --- | --- | --- |
| 两路南向 | 最多32台 | TCP，可配置其余口为RTU或停用 | 每路最多16台；可只启用实际接线台数。 |
| 三路南向 | 最多48台 | TCP，余下一口可作RTU | 不能将同一串口同时作主站和从站。 |
| 四路南向 | 最多64台 | TCP | 四个串口均用于仪表，没有北向RTU口。 |

新机生成配置按COM1起每口16台、站址1～16分配；这是默认绑定，现场可调整。现有配置升级绝不按这个规则重新分配：原1～32号槽位、COM、地址、名称、绑定版本及权限全部保留，仅追加33～64号槽位的版本。FW站址范围仍为1～243，同一总线地址唯一。

## 客户地址及兼容性

原1～32号单台摘要、详情、参数和控制地址均保持。新增33～64号沿用原公式：摘要B=1000+24×(n−1)，详情D=3000+144×(n−1)，参数P=20000+48×(n−1)，控制C=30000+12×(n−1)。64号对应B=2512、D=12072、P=23024、C=30756。指令、状态、错误及独立停止操作方式保持。

| 仪表范围 | 液位和平均温度 | 当前密度、质量及有效位 | 每条数量与偏移 |
| --- | --- | --- | --- |
| 1～32号 | 15000 | 15100 | 各96字，k=3×(n−1)。原地址保留。 |
| 33～64号 | 15200 | 15300 | 各96字，k=3×(n−33)。新增两区。 |

全64台主要值共四次读取；每条仍最多125字，不跨区域。液位连续数组现为128字，必须拆读，例如14000起124字、14124起4字。控制768字可分6次120字和最后48字；完整摘要1536字可分12次120字和最后96字。多次响应不是严格同步快照。

FC04地址2起2字返回[3,64]，地址27起3字返回[16,3,12]，依次为每口容量、控制能力和步长。旧客户仅访问1～32号的已知地址可继续使用；写控制前若硬编码容量32，须更新兼容判断。不能把北向版本3当作容量32。旧32台软件返回[3,32]及每口8，不能访问新增槽位。

## 动作认证

每次实际下发浮子动作前，程序先读取新鲜IR51/52并检查网关前置条件，再写HR129=0x10D9；收到认证成功应答后才写HR699动作位，随后回读。下降编号6转换为HR699=0x0100；独立停止同样先认证。认证失败、未通过前置条件、只做复位或同周期重复请求都不会补发动作。认证由网关完成，客户不需要另写南向HR129。

2026-10-20按用户确认，软件0.4.1取消IR51 bit15发送前拦截和回读确认条件；该位只按原值显示本地/远程信息。仍读取新鲜IR51/52；0.8.3起IR52用于故障诊断，允许带故障码操作；每次动作认证及权限条件保留。仪表本身是否接受，以应答及回读为准；状态3不代表机械完成。旧版“仪表非远程，未发送”的状态4/错误2保留，可人工写0复位后另发新动作，升级不自动复位或补发。见[ADR-017](../decisions/ADR-017-取消IR51远程位控制门槛.md)。

平均测温仍由上位机组织完整任务；本版按每次动作认证，未实现“一任务仅认证一次”的专用上下文，也未增加停留后强制新读I6接口。原任务说明中的待适配事项不能当作已实现功能。

## 升级与回退

配置由schema2的32槽位转换为schema3的64槽位；schema1旧配置不自动解释。安装器先校验、停止服务，备份原数据库、gateway.json及service.env，再原子保存schema3配置。数据库首次打开时在事务内扩大control_slots约束，升级到schema3，历史、审计和原控制JSON保留。旧状态1/2启动后仍转5/9，不重放；原状态5不被清除。数据库文件名继续为gateway-v2.db。

设备包仍为13个运行必需文件，不包含文档、源码或用户资料。NORTH_VERSION文件为3.1，用于容量扩展后的回退兼容检查；它不是FC04地址2的整数值。安装失败时不自动退回0.3.x，不自动恢复旧库。回退只允许同一schema3及64槽位兼容系列，并须核对目标程序。旧程序读取新增槽位或新版库不完整，因此不能靠改标记、删库或换备份强行回退。

设备端使用已上传并校验的新包，以下向导或手动安装二选一。完整上传、密码、自启及手动部署仍见[说明10](10_运行部署与维护.md)。

```sh
# 指定本次已经解压并核对摘要的ARM64包目录。
gateway_new_pkg=/tmp/gt6757s-0.4.3-20261027-r1-linux-arm64

# 推荐：新机引导填写参数，已有设备保留参数并进行升级。
sh "$gateway_new_pkg/deploy/install.sh" --guided "$gateway_new_pkg"
```

若采用手动安装，使用以下命令替代上面的向导命令，不要重复安装同一标签：

```sh
# 手动执行安装器，备份及配置迁移仍由安装器完成；新机后续手动设置管理员密码。
sh "$gateway_new_pkg/deploy/install.sh" "$gateway_new_pkg"

# 检查新核心已正常响应内部健康检查。
/home/level-gateway/current/bin/gateway-core --health-check --ipc unix:/home/level-gateway/data/core.sock

# 检查两个服务监督器状态；随后登录网页核对0.4.1及原绑定。
sh /home/level-gateway/current/deploy/service.sh status

# 查看正式配置版本，预期schema_version为3；不要直接手改版本数字。
head -n 5 /home/level-gateway/config/gateway.json
```

升级后强制刷新浏览器，核对所有原仪表的COM、站址、名称和读取地址，再逐台增加新仪表。默认HTTP、TLS两项空值、WATCHDOG空值和原控制授权均保持；安装不会自动开通新动作。

## 刷新时间及验收

默认fast_ms=3000及detail_ms=30000保持，3秒是目标，不是满载承诺。快速通信按每台90字符、每字符11位、三次额外处理各30ms预算：T=16×(90×11/baud+0.09)，4800bps约4.74秒，9600bps约3.09秒；还未计详细采集、参数、控制和异常超时。四口并行，不将四口轮询时间相加。

4800bps每口16台可先试fast_ms=6000、detail_ms=60000，再根据实测调整；若修改快速周期为6秒，有效窗口随之为18秒。保留默认3秒时窗口仍为9秒，不能声称扩容后仍每3秒更新。任何参数调整均须厂家评估现场要求，升级不会擅自改已有周期。单台断线、全线离线和多点数据开启时都要记录P50/P95/最大年龄、告警和停止延迟。

64台按每条128B估算、每分钟记录、30天原始约337.5MiB，另有SQLite索引/WAL；原256MiB上限可能早于30天淘汰历史。上限及保留天数仍沿用现场配置，容量不能作为保证保留30天的承诺。

软件检查覆盖旧绑定迁移、槽位16/17/32/33/48/49/64、四块批量区、125字限制、64号控制持久化及认证顺序。真实每口16台时效、总线电气条件、断电、故障场景及72小时仍需上板验收。实体SYS驱动沿用用户已确认正确的实现，本轮不改驱动。

满载调度保障：快速轮询每完成一轮，保留一次低频采集机会；温度、密度、模拟量与参数按启用情况轮转，避免连续快速任务使慢速项永久饥饿。低频目标仍可能延后，保障获得机会不等于承诺30秒满载完成。停止仍在交换边界优先。0.4.0-r1仅为本机候选，0.4.0-r2补齐此保障；当前0.4.1继续保留。
