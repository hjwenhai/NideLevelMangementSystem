# 网页上传升级操作说明

当前正式包为 **0.8.3-20261117-r1**，支持仪表带故障码下发已开通的操作和独立停止。旧控制结果由人工核查处理，升级后按实际故障继续显示告警。已授权的 0.8.1 在网页直接上传对应架构的新包，校验后确认安装，保留现有 IP、仪表配置、授权、管理员和历史。0.6.0 样机仍按下方过渡步骤先进入 0.8.1，再按常规步骤升到 0.8.3。

> 2026-11-09／软件0.8.1：统一Modbus TCP设置。“系统维护→网络设置”选择接入网口；“端口与仪表”只改TCP服务端口，默认502，并显示可复制的只读访问地址。导入配置保留本机接入IP，只导入服务端口；普通配置接口禁止改IP。网络试用、永久授权、容量及客户协议保持。

> 2026-11-09：软件0.8.0新增一台网关一份离线永久授权。已有旧版设备可通过下述过渡包在网页上办理授权，再安装正式版；新机先开放管理网页，导入授权并人工重启后采集。授权申请、发放和旧版迁移见[说明33](33_设备永久授权与厂家发放说明.md)。正常升级保留本机授权，客户Modbus协议不变。

> 2026-11-08：软件0.7.0新增“系统维护 → 网络设置”，支持两个网口静态IP、掩码与单默认网关，联动TCP监听；180秒人工确认、超时和断电恢复，沿用厂家FUN临时恢复IP。操作与上板验收见[说明31](31_网络设置与失联恢复.md)。默认HTTP、看门狗关闭，北向V3.2-D2不变。


适用版本：软件0.6.0起，GT6757X／GT6757S的Buildroot部署，使用项目自带的service.sh管理服务。北向通讯协议仍为V3.2-D2，64槽位、每南向COM最多16台。

## 1 客户怎样升级

### 0.6.0 样机通过网页升到 0.8.1（GT6757S、ARM64）

请准备下表两份文件，使用样机原来的网页地址和管理员密码。已安装支持网页升级的 0.6.0 样机可直接安装过渡包。安装前记录两个网口 IP、上位机使用的 TCP 地址、已启用仪表数，再选一个已知时段导出历史 CSV，便于升级后核对。

| 顺序 | 文件 | 用途 |
| --- | --- | --- |
| 第一次安装 | `gt6757s-0.7.0-20261109-r2-linux-arm64.gwup` | 网页授权过渡包 |
| 第二次安装 | `gt6757s-0.8.1-20261109-r1-linux-arm64.gwup` | 0.8.1 正式版 |

1. 进入 **系统维护 → 网页升级**，选择过渡包，点“上传并校验”，核对待安装版本为 **0.7.0-20261109-r2**。安排维护窗口，核查浮子状态并处理已有控制结果，勾选确认，点“确认安装新版本”。安装期间采集和上位机通讯短暂中断，请保持供电。
2. 用原地址重新登录，查看“当前版本”是否已变为过渡版，并确认仪表恢复采集。进入 **系统维护 → 设备永久授权**，点“下载本机申请文件”，将下载的 **.gwreq** 发给厂家。等待厂家回件期间可正常使用样机。
3. 收到厂家返回的本机 **.gwlic** 后，仍在“设备永久授权”选择该文件，勾选来源确认，点“校验并保存授权”。看到 **本机永久授权校验通过** 即可继续，无需单独重启。若提示设备不匹配，请用这台样机重新下载申请并联系厂家。
4. 回到“网页升级”，选择第二份正式包，核对待安装版本为 **0.8.1-20261109-r1**。再次确认维护窗口及现场状态后安装。程序会备份配置、管理员、授权和数据库，继续使用原有配置与历史记录。
5. 从原地址重新登录，确认当前版本、永久授权状态、仪表数量和实时读数，再用原上位机地址试读。按升级前相同槽位和时间段导出 CSV，核对升级前的记录。在两次安装的停服时段可能出现采样间隔。

如果样机当前是 0.7.0-20261108-r3，也可从第 1 步开始。已授权的 0.8 设备按下面的常规步骤升级。看不到网页升级入口时请将完整版本号提供给厂家。授权或签名校验失败时保留当前程序，按页面提示核查；若显示“需要人工维护”，联系厂家并保留现场日志。

过渡包的文件校验值见 [SHA-256 清单](../output/packages/SHA256SUMS-0.7.0-20261109-r2.txt)。如果样机曾经回退，本次过渡网页会核对设备上已有的正式版目录；一致时直接复用，提示文件不一致时请联系厂家。

### 已授权设备的常规升级

1. 将厂家发来的`.gwup`升级文件保存到电脑。电脑连接网关所在网络，用浏览器打开原管理地址并登录。
2. 进入“系统维护→网页升级”，选择文件，点“上传并校验”。上传不切换程序，采集继续运行。
3. 核对当前版本、待安装版本、设备架构和更新说明。校验不通过时停止操作，将提示发给厂家。
4. 安排维护窗口，确认现场仪表无动作，各控制通道已正常结束并由原控制方核查、复位。勾选现场确认，点“确认安装新版本”。
5. 等待升级。网页可能暂时无法连接，采集与Modbus通讯会中断；不要断电，也不要反复点击安装。
6. 网页恢复后会自动刷新加载新页面，请重新登录，查看升级结果。确认显示“升级成功”，再检查仪表数量、当前值、数据年龄和客户上位机通讯。

常规升级每次上传一个`.gwup`文件，不需要U盘、SSH或逐项输入命令。首次启用网页升级仍须由厂家安装本版基础程序。手机、平板可通过同一路由器的Wi-Fi访问网页并选择已下载的文件；首次现场验收建议使用有线电脑。

**升级网关不等于停止浮子。** 升级不会自动停止、复位或重新发送仪表动作。尚未处理的控制结果会阻止开始升级，不能靠升级绕过状态5。

## 2 文件与适用范围

| 文件 | 用途 |
| --- | --- |
| `gt6757s-0.8.1-20261109-r1-linux-arm64.tar.gz` | 厂家首次安装或现场手动维护。当前已知设备为ARM64。 |
| 同名`.gwup` | 带厂家数字签名的单文件网页升级包。0.6.0基础版安装后，后续使用更高发布标签的包。 |
| `linux-armv7`包 | 只给经探测确认32位用户态的设备使用，不能用于已确认的ARM64设备。 |

不接受直接上传`.tar.gz`、用户自行重新压缩的文件、签名不符、型号或架构不符、相同或更旧发布标签的文件。最大上传32MiB，展开运行文件最大64MiB；空间检查还会为数据库一致性备份预留容量。

网页升级只更新网关应用，不更新Linux内核、系统镜像、IP地址、开机引导或厂家固件。仅接受升级协议1、北向3.2、配置及数据库schema3的兼容包。未来涉及这些格式变化时，由厂家另行提供迁移方案。

## 3 升级时保留什么

保留本机永久授权文件config/license.json、实际仪表绑定、四口角色及串口参数、Modbus监听、网页端口及HTTP/HTTPS方式、管理员密码、历史数据、控制及复位记录、RTC校时记录和已有签名信任公钥。TLS、看门狗和硬件写许可沿用已有设置；默认HTTP、看门狗关闭。

从 0.6.0 经本过渡包升到 0.8.1 时沿用系统网口 IP。新版项目服务的网页会在两个IPv4网口监听原端口，便于FUN临时恢复后访问；这与修改网卡IP是两回事。只有之后主动使用“网络设置→应用并试用”才会修改网卡参数。

新0.8执行器升级时，将本机授权一并备份。旧0.7执行器首次升级不会额外备份授权，但会保留厂家预先放入config目录的文件。停止服务后，配置、服务参数、管理员文件、公钥、已有时钟记录及SQLite一致性备份保存到`data/upgrade-backup-任务编号/`。控制记录随原数据库继续使用；自动恢复旧程序时不恢复旧数据库，不删除或倒退控制审计。

本版兼容包不要求新增service.env参数，因此网页升级不重写现有参数。新版本首次配置模板随程序保存，已有现场配置不会被模板覆盖。手动安装器继续保留“仅补缺失项”的行为。

## 4 状态怎么看

| 状态 | 含义与处理 |
| --- | --- |
| 校验通过，等待确认 | 文件已校验，程序未切换。可核对说明后安装，也可重新上传其他合格文件。 |
| 已受理／重新校验 | 已记录任务和来源，阻止新的控制、配置、校时、改密和程序重启。读取可继续，随后会停服。 |
| 停服与备份／切换程序／启动服务／启动验证 | 后台独立执行，网页断开不会取消任务。不要断电或重复安装。 |
| 升级成功 | 实际运行版本、采集调度、网页及北向寄存器映像检查通过。还须核对现场数据和客户通讯。 |
| 已恢复原程序 | 新程序未通过启动检查，已恢复本次升级前的兼容程序。不要立即重复安装，先联系厂家查原因。 |
| 升级未执行 | 准备检查失败，原程序未切换；按提示处理。 |
| 需要人工维护 | 执行器异常退出、升级期间重新上电或恢复失败。保持控制互锁，厂家核查后处理；不能自行删锁或改状态文件。 |

校验失败不会替换先前已校验的待安装任务。重复确认同一已受理任务不会再次启动执行器。网页恢复后需要重新登录；会话退出不代表升级失败。

## 5 厂家首次启用

按[运行、部署与维护10](10_运行部署与维护.md)第3、4和10节上传、校验并手动升级到0.6.0基础包。向导和完整手动步骤均保留，每条命令有中文注释。运行包只有16个必要文件，用户文档和签名私钥不上传设备。

安装器首次将运行包内的公钥模板复制到`config/update-trust.json`；已有公钥不覆盖。使用本版监督脚本启动后，“系统维护→网页升级”可用。第一次不要向网页上传相同0.6.0-r1包验证成功：相同发布标签会被拒绝。应在试验设备使用厂家提供的下一发布标签包完成验收。

## 6 厂家检查与异常恢复

以下在设备SSH或Console执行。先保留记录，再判断当前版本、服务和任务状态；不要删除数据库或install.lock。

```sh
# 查看当前程序指向的版本，判断切换是否已经发生。
readlink /home/level-gateway/current

# 查看持久化升级记录，记录任务id、阶段、前后版本和错误提示。
cat /home/level-gateway/data/upgrades/state.json

# 查看升级执行器最近100行日志，定位签名、备份、切换或启动检查失败点。
tail -n 100 /home/level-gateway/logs/upgrade.log

# 查看采集服务和网页监督器状态，不触发重启或仪表动作。
sh /home/level-gateway/current/deploy/service.sh status
```

确认供电稳定、当前程序完整、服务正常且全部控制空闲后，厂家才可使用恢复检查。将下面任务编号替换为状态文件里的32位id。此命令只检查当前实际运行程序并确认任务终态，不重新安装、不自动清除仪表控制记录。

```sh
# 填写本次待处理的升级任务编号；须从state.json核对，不能猜测。
gateway_upgrade_id=填写32位任务id

# 检查当前兼容程序及服务；通过后解除升级互锁，失败则保持锁定并报告原因。
/home/level-gateway/current/bin/gateway-updater recover --base /home/level-gateway --id "$gateway_upgrade_id"
```

若服务尚未恢复，先按说明10检查日志、配置及兼容版本，再启动正确程序。恢复工具不会自动选择其他版本，不替代现场判断。停电测试、断网、实际eMMC空间不足及Buildroot服务切换须在试验设备验收。

## 7 厂家打包与密钥

`tools/package.ps1`首次在厂家电脑`private/update-signing.key`生成Ed25519签名私钥，公钥模板为`deploy/update-trust.json`。私钥目录已从版本管理排除；请单独备份并控制访问。丢失私钥后不能给已部署公钥的设备继续签发升级包。不要随包发给客户，也不要上传设备。

```powershell
# 在项目的设备采集网关目录执行；构建程序、网页并运行Go回归。
pwsh -File tools/build.ps1

# 使用PowerShell 7生成新的运行包和签名升级包；发布标签必须递增且不能覆盖旧包。
pwsh -File tools/package.ps1 -Version '0.8.1-20261109-r1'

# 计算发给客户的升级文件摘要，交付记录须以最终文件的实际结果为准。
Get-FileHash -LiteralPath './output/packages/gt6757s-0.8.1-20261109-r1-linux-arm64.gwup' -Algorithm SHA256
```

构建脚本与打包脚本均要求PowerShell 7；若电脑未安装pwsh，按电脑操作说明22选择已有PowerShell 7完整路径，不在设备安装开发工具。

## 8 验收范围

本机软件测试使用临时目录、模拟液位计、独立测试签名密钥及真实编译的核心、网页、升级执行器，验证上传、鉴权、防篡改、控制互锁、两服务切换和失败恢复。测试包不是客户交付包，Windows服务桥不等同于Buildroot服务实测。

板端验收至少包括：首次手动升级、下一标签网页升级、升级前后账号及配置一致、历史及控制记录保留、双网口通讯恢复、SYS灯、启动失败恢复、上传中断、切换阶段断电后的人工恢复。未完成板测前不标注“现场验收通过”。

## 与网络修改互斥

0.7.0网络试用期间不能上传、确认或手动安装应用升级包。先完成网络人工确认或等恢复结束，再按本说明升级。升级自身保留当前IP；新版网页监听两个IPv4网口，首次升级后需验证两网口网页登录。FUN及失联恢复见说明31。
