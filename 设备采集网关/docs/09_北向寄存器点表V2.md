# 北向寄存器点表 V2

中文详解版，更新日期2026-10-10；对应软件0.2.0。本文解释上位机如何读GT6757S网关，不是让上位机直接轮询每台液位计。地址、字数和编码保持V2原样，仅补充中文说明。布局来自`protocols/north-v2.json`，说明由`tools/point_map_notes_zh.py`维护，运行`tools/generate_map.py`生成本文件。

本文件是**当前软件0.2.0/V2的厂家内部完整参考**，其中邮箱控制仅描述现有V2。目标客户使用[统一协议12](12_客户通讯协议V3.md)，新简易控制见[目标点表15](15_北向寄存器点表V3.md)，尚未实现。本文不含V3新控制，不能用V2邮箱章节指导未来客户；厂家配置和诊断仍参照本文及部署文档。

第一次阅读建议先看第1～2节和第6节：先理解地址/字数，再尝试读取一台仪表。需要32台批量读取时看第7～8节；判断数值是否可用时看第15～16节；需要发送动作时看第12～14、17及20.2节。

## 1 先理解这张表

网关自主从液位计采集，再将最新值放入缓存。上位机读这里的寄存器，读到的是缓存；多读几次不会让液位计加快采样。槽位1～32是网关给仪表分配的逻辑编号，COM口与液位计站地址是另一组编号。槽位9可以绑定COM2/站地址1，所以上位机不能直接把“槽位9”当作“液位计站地址9”。

每路南向最多8台。16台通常2南向＋1北向RTU，24台3南向＋1北向RTU，32台4南向，只能通过TCP北向访问。具体绑定来自配置，点表不强制某个槽位属于某个COM。

### 1.1 表格列怎么读

| 列名/术语 | 中文备注与使用方法 |
| --- | --- |
| 起始地址 | 区域第一个寄存器在Modbus报文中的地址，从0开始，单位是“寄存器”，不是字节。 |
| 步长/每项字数 | 一个槽位、一口或一个邮箱占多少个16位寄存器；下一项地址增加这个数。 |
| 数量 | 该区域容纳多少项，如摘要32项代表32个槽位，并不表示只占32字。 |
| 相对偏移 | 字段距本项基址多远；实际地址=该项基址+偏移。 |
| 字数 | 一个字段占几个16位寄存器；1字=16位=2字节。读取字数不能按字节数填写。 |
| uint16/uint32/uint64 | 16/32/64位无符号整数，分别占1/2/4字。64位时间戳和启动标识不要转成低精度浮点数。 |
| int16/int32 | 有符号整数，占1/2字；必须按补码处理，温度/变化率可以是负数。 |
| bits（位标志） | 每一位各有含义，多位可以同时置1；例如quality=131是1+2+128，不是状态“131号”。 |
| 状态编号 | 单一枚举，如命令state=4；不能像位标志那样拆成若干条件。 |
| 只读/命令 | 只读区FC03、FC04都可读、不可写；命令区仅FC03读，前64字可用一条FC10提交。 |
| IR/HR | 在原液位计侧分别表示输入寄存器/保持寄存器。网关这里的零基地址是另一个映射，不能直接套原IR/HR地址。 |

### 1.2 地址、字序和数值换算

全部地址为十进制PDU零基地址。读槽位1摘要，就是起始1000、数量24。某些组态工具输入“一基地址”或显示3xxxx/4xxxx，需要按该工具的规则转换；不能一律给本文地址加40001后写入报文。

同一寄存器在报文中高字节在前；多寄存器字段高字在前。32位无符号数`U=W0×65536+W1`。32位有符号值在U≥2147483648时为`U−4294967296`。16位有符号值在W≥32768时为`W−65536`。64位由四字依次拼接，W0最高；不是IEEE754浮点编码。

| 读取的原始字/值 | 中文备注：正确显示结果 |
| --- | --- |
| 液位两字W0=1、W1=34587 | 合成100123，再÷10→10012.3mm；不能把两字分别显示成两个液位。 |
| 平均温度W=2001 | 按int16解码后÷100→20.01℃。 |
| 平均温度W=0xFB1E（64286） | int16值−1250，再÷100→−12.50℃，不是642.86℃。 |
| 密度W=8510 | ÷10000→0.8510g/cm³；若上位机用kg/m³，÷10→851.0kg/m³。 |
| 数据年龄=3500 | 毫秒÷1000→3.5秒；不是1970年起的时间戳。 |
| UTC毫秒时间戳 | ÷1000得到Unix秒，按UTC转换为日期；显示北京时间再用UTC+8。先判断时间可信位。 |

## 2 最容易上手的读取流程

首次连接先用FC03或FC04读地址0、数量28：响应数组W[2]（第3个寄存器字、偏移2）应为协议版本2，W[3]应为最大槽位32，W[27]应为单口上限8。读到不同值时停止按本表解析及发送动作。RTU用网关配置的站号/波特率/校验和CRC；TCP用配置的站号（默认1）及端口（实机模板502）。功能码FC03/FC04/FC10分别是十六进制03/04/10，即十进制3/4/16。

| 目的 | 功能码 | 起始地址 | 数量（字） | 中文备注：拿到什么、怎么用 |
| --- | --- | ---: | ---: | --- |
| 确认网关版本和状态 | FC03或FC04 | 0 | 28 | 每次新连接/疑似重启先读，保存boot_id，确认V2/32/8及时间/模拟标记。 |
| 读槽位1完整常用数据 | FC03或FC04 | 1000 | 24 | 最容易调试：同一响应含液位、温度、密度、质量、年龄、绑定版本。 |
| 读槽位9完整常用数据 | FC03或FC04 | 1192 | 24 | 1000+(9−1)×24=1192；槽位9不必然是南向地址9。 |
| 连读槽位1～5摘要 | FC03或FC04 | 1000 | 120 | 每24字一台；数量120，不是120字节。 |
| 读32槽液位＋平均温度 | FC03或FC04 | 15000 | 96 | 每3字一槽，前2字液位、第3字温度；还要读下一行判断有效性。 |
| 读32槽当前密度＋质量＋有效位 | FC03或FC04 | 15100 | 96 | 每3字一槽，依次密度/quality/valid；与前一响应配合显示三项数值。 |
| 只读32槽液位 | FC03或FC04 | 14000 | 64 | 只含液位原值，没有年龄/质量/有效位，需另读14500/14600的32字数组。 |
| 读TCP邮箱4执行结果 | FC03 | 40576 | 64 | 40000+4×128+64；不是FC04，查询当前命令来源/序号和终态。 |

32槽完整摘要总计768字，可依次读取`1000/120、1120/120、1240/120、1360/120、1480/120、1600/120、1720/48`（起址/数量）。即7次。32台液位、温度、密度、质量和有效位共192字，标准Modbus单次最多125字，必须分批，不能承诺一条读完。

批量区按槽位顺序排列，未使用槽位也占位置。槽位s在响应里的字偏移为3×(s−1)：槽位1偏移0、槽位2偏移3、槽位32偏移93。有效位为0的字段显示缺测“—”，不要将原字0当作掉线标志，真实测量也可能为0。

## 15 数据质量位（quality）

本表“bit编号”从0表示最低位；判断方式为`quality & 掩码 != 0`。掩码等于2的bit次方，可同时有多个条件。位未置1不必然说明相反条件已被实机证实。

| 中文名称 / 程序名 | bit编号 | 十六进制掩码 | 十进制掩码 | 中文备注 |
| --- | ---: | --- | ---: | --- |
| 已采集过 `initialized` | 0 | 0x0001 | 1 | 至少一次采集组成功，已有缓存数据；不是三个快速组均已成功。0表示尚未读到任何组。 |
| 近期在线 `online` | 1 | 0x0002 | 2 | 该台最近任一组成功距今不超过3×fast_ms。本版默认约9秒窗口；详情成功也会刷新这一判断，所以在线不保证液位等字段新鲜。 |
| 快速数据缺失/过期 `stale` | 2 | 0x0004 | 4 | 至少一个快速组从未成功、被判不支持或年龄超过3×fast_ms。按valid逐字段判断，不必把所有数值一律作同一种缺测。 |
| 仪表故障 `instrument_fault` | 3 | 0x0008 | 8 | 曾读到的IR52原字非0，表示仪表报告故障。可能来自保留旧故障字，应结合fault有效位和年龄。 |
| 未绑定/停用 `disabled` | 4 | 0x0010 | 16 | 槽位未绑定或已停用。本版此时quality=16、valid=0；其它缓存位置可能保留旧原值，不显示成有效测量。 |
| 快速寄存器不支持 `unsupported` | 5 | 0x0020 | 32 | 至少一个快速组被南向异常02判为不支持；这个快速组不会继续正常轮询，需核实固件/地址及重新配置。 |
| 时间未确认 `time_untrusted` | 7 | 0x0080 | 128 | 当前时钟未确认，或任一快速组采集时未标可信。数值可以有效，但UTC采集时间不能视为可靠时间。 |

bit6和bit9～15当前未定义，通常为0，上位机忽略。举例：quality=3表示已采集＋近期在线；131=3+128表示另有时间未确认；387=3+128+256表示还发生快速读取异常。此时有效位可能仍127，因为旧值尚在时效窗口内；不能只用valid就声称“本次成功更新”。

## 19 采集组状态位和SYS灯模式

采集组状态在详情的每组元数据偏移0中。bit从最低位开始，与原始IR已读位图“IR0对应最高位”的规则不同。

| 组状态bit | 掩码 | 中文含义 | 中文备注 |
| ---: | --- | --- | --- |
| 0 | 0x0001 | 此组曾读成功 | 旧缓存可能仍存在，不保证最近一次成功或当前新鲜。 |
| 1 | 0x0002 | 此组最近一次有错误 | 与bit0可以同时存在；成功后清除此错误位，累计失败数不清零。 |

## 20 两个完整解析示例

### 20.1 读槽位9的摘要

用FC04，起始1192，数量24。假设返回字数组W，W[0]=131、W[1]=127、W[4]=1、W[5]=34587、W[6]=2001、W[7]=8510。

| 步骤 | 中文备注：上位机应如何处理 |
| --- | --- |
| 看W[0]质量=131 | 1+2+128：曾采集、近期在线，但时间未确认；不显示“所有条件完全正常”。 |
| 看W[1]有效位=127 | 7类字段都在有效窗口，可显示数值；仍需保留质量警告和数据年龄。 |
| 算液位 | (1×65536+34587)÷10=10012.3mm。 |
| 算平均温度 | int16(2001)÷100=20.01℃。 |
| 算当前密度 | 8510÷10=851.0kg/m³。 |
| 看W[16]～W[17] | 合成32位最大组年龄，显示为秒；若0xFFFFFFFF则提示快速组尚未完整就绪。 |
| 看W[18]、W[19] | 分别是实际COM编号与该总线液位计地址；不由槽位9自行推算。 |
| 看W[20]～W[21]绑定版本 | 写动作前重新确认，带入邮箱请求偏移10～11；配置改绑后旧值不能继续用。 |
| 看W[12]～W[15]时间与W[22] | 时间是最近完整快速采集的UTC毫秒，W[22]=0时标为时间未确认；不要当内部测量时刻。 |

### 20.2 TCP邮箱4向槽位1提交上升动作（编码示例）

此例会请求运动，应只在已批准的现场/模拟环境使用。先读整机0起28字确认V2和当前boot_id，再读槽位1摘要1000起24字取绑定版本。假设该来源本次启动还没提交过动作，则sequence=1；已有命令时须继续递增，不能照抄1。

| 请求偏移 | 填写内容 | 中文备注 |
| --- | --- | --- |
| 0 | 2 | 请求格式V2，不能填1。 |
| 1～4 | 整机地址6～9的四字原样复制 | 当前启动标识；重启后要重新读。 |
| 5～6 | 0、5 | client_id=5，匹配TCP邮箱m=4。 |
| 7～8 | 0、1 | 32位sequence=1，仅用于本来源本次启动的第一个请求。 |
| 9 | 1 | 目标槽位1，不是写南向站号1。 |
| 10～11 | 槽位1摘要偏移20～21原样复制 | 当前绑定版本，不固定写1。 |
| 12 | 1 | kind=1，受控动作。 |
| 13 | 699 | 原液位计目标HR699。 |
| 14 | 1 | 仅1个动作字。 |
| 15 | 0x0002 | 上升单动作位。 |
| 16～62 | 全部0 | 负载未用位和保留位都必须补零。 |
| 63 | 0xA55A | 完整提交标记。 |

使用**一条FC10（十六进制10，即十进制16）**，起始40512、数量64、数据字节数128提交。FC10正常应答仅表示网关接受该请求/重复确认，不能据此认为仪表已上升。接着用FC03读40576起64字，核对结果client_id=5、sequence=本次序号、slot=1及绑定版本，再等状态4/5/6/7。

如果提交应答丢失，先查邮箱；需要重交时保持同一boot/client/sequence和完全相同的64字，已受理请求由网关去重。不要换新sequence制造第二次物理动作。启动标识变化或结果6时，先核实仪表；网关不会自动重放上次未决动作。

## 21 异常应答与读取一致性

| 异常码（十六进制/十进制） | 中文名称 | 中文备注与处理 |
| --- | --- | --- |
| 01 / 1 | 不支持功能 | 使用FC03/04读数据、FC03读邮箱、FC10完整写请求；其它功能本版不支持。 |
| 02 / 2 | 非法地址或入口权限 | 地址落空洞/超出32槽、跨区域、写只读区、FC04读邮箱、入口allow_writes关闭、写了不属于来源的邮箱、没有从请求基址整写64字，或动作类别/目标地址/动作负载字数不符合本版限制。核对区域、入口及请求形状。 |
| 03 / 3 | 非法值或数量 | 普通读取数量越界、报文长度/字节数不符、旧版本、错误启动标识/绑定/序号、补零或提交字错误、动作不在白名单、维护模式或真实模式未启用--hardware-writes等。检查字段和配置；与入口allow_writes关闭返回02区分。 |
| 04 / 4 | 服务处理/审计失败 | 例如持久化受理失败，动作不会先执行再补审计。检查存储与错误日志。 |
| 06 / 6 | 网关忙 | 邮箱/目标/队列正在占用，先查询已有请求，不高速重复写入。 |

异常响应的功能码为原功能码加0x80；例如FC04非法地址返回0x84、异常码0x02。RTU坏CRC、广播地址0和非本站号不应答；TCP非法MBAP可能直接断开连接。没有应答与收到异常应答不是一回事，上位机应设置超时并记录区别。

**一致性和时效：**每条请求从缓存获取一份快照；不同请求可能跨过一次采集/改绑。两个批量区没有跨请求锁定快照的功能，不能保证其值和有效位属于完全同一采集时刻。需严格对应时优先读同一台24字摘要；多段详情可前后核验该槽绑定版本和更新序号，变化则重新读取。它们仍然是分组采集，不是仪表多字段同步采样。

**保留值和时间：**失败保留旧原值、旧采集时间，不把读取上位机的当前时间写成新采样时间。重启后缓存重新采集；未绑定/停用看quality bit4和valid=0。快速目标默认3秒、详情目标30秒、参数10分钟、历史记录60秒都是不同周期，实际刷新仍需板测。

**版本边界：**当前仅支持V2读映射和V2动作请求，旧V1尾段/请求拒绝，普通参数写入尚未实现。不要自行把参数区地址作为可写目标。完整需求见[需求文档](01_需求讨论草案.md)，运行方式及现场限制见[部署文档](10_运行部署与维护.md)。
