# GT6757S 网页授权过渡包复核

起始包为 0.6.0-20261029-r3，过渡包为 0.7.0-20261109-r2，目标为已发布的 0.8.1-20261109-r1，三个包均为 linux-arm64。

| 检查 | 结果 |
| --- | --- |
| 发布文件 | 用 0.6.0 和普通 0.7.0 随包的信任公钥分别验证过渡包成功。过渡包共 14,356,408 字节。三个包的 SHA-256 与各自发布清单一致。 |
| 过渡包内容 | 比对签名清单中的 16 个运行文件。与普通 0.7.0 相比，变更文件为网页程序、升级执行器、RELEASE 和 SHA256SUMS。采集核心、服务脚本、配置模板和信任公钥的文件摘要一致。 |
| ARM64 联调 | 使用本机 QEMU、三个实际发布包、临时数据库、虚拟设备标识和模拟仪表。0.6.0 管理网页接收过渡包。过渡网页导出本机申请，在无授权时拒绝确认安装，接受匹配的永久授权。0.8.1 正式核心独立验证保存的授权成功。 |
| 运行及历史 | 两次切换均通过运行版本、网页和采集探测。同一 Modbus TCP 地址均可读到 64 槽位容量。原配置、服务参数和管理员文件逐字节一致。按原时间和槽位从数据库重新查询，0.6.0 生成的历史液位记录一致。 |
| 异常处理 | 未登录申请、缺少 CSRF 校验、其他设备授权均被拒绝。确认安装前重新读取磁盘授权，损坏的授权被拒绝。先前回退留下的目标目录与签名清单一致时可复用，有多余文件或程序损坏时拒绝。 |
| 回归 | 常规及过渡构建的 Go 回归最终均通过。Windows 网络参数试用用例在部分运行中出现状态保存失败并自动回退，单独复跑与最终整套复跑通过，偶发原因尚未确定。 |

ARM64 联调使用临时服务控制器启动和停止进程，执行升级事务及备份。现场 Buildroot 服务监督、双网口物理连接、实际硬件标识断电后的稳定性和真实液位计须在样机上验收。未连接客户设备。
