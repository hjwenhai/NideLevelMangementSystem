r13网关远程液位修改修复与升级说明

2026-10-30 · GT6757X网关Modbus TCP / RTU接入。原r12部署指南与操作说明仍适用，本页说明本次差异。

本次解决什么问题

网关自身页面可以修改液位，但管理系统在提交前提示“设备状态无效，未受理新动作”。旧版把仪表状态、故障码的有效性误关联到可选16点密度数据组，未启用该组或该组过期时会错误拦截；现改为按实际状态采集组判断。网关参数校准也不再误用浮子运动的远程模式位限制，与网关参数修改流程保持一致。直接RTU仪表沿用原检查。

真实状态组缺失、过期、仪表有故障或液位无效时仍会阻止修改。提示会具体指出缺少液位/浮子位置、仪表状态或故障码，不需要为使用远程液位修改而启用可选16点密度采集。

已安装r12的客户怎样升级

  1. 先结束或核查正在进行的仪表操作、平均测温任务。由现场人员确认仪表状态；不要在操作尚未结束时强行升级。
  2. 在系统的数据维护功能保存一份业务备份，关闭桌面客户端。记录原安装目录及业务数据目录；默认数据在C:\ProgramData\Naide\LevelManager，授权保护目录为其同级LevelManager.authorization。
  3. 在Windows“服务”中找到“液位管理系统后台”，停止该服务。本次升级会短暂停止采集，安排合适时间操作。
  4. 将r13完整ZIP解压到新目录，运行根目录“安装.cmd”，沿用原来的安装和业务数据目录。若原来采用自定义目录或端口，请按原部署参数运行Install.ps1；不要改成新的空数据目录。安装器会校验文件并建立新版本目录，不覆盖旧版本目录。
  5. 安装完成后服务恢复运行，从桌面打开系统，确认左侧版本为r13，原罐号、通讯、历史和授权仍在。新安装及升级的采集启动规则沿用部署指南；必要时进入系统启动采集。

不需要卸载旧版，不需要重新建罐或重新导入授权。本次数据库仍为schema16。不要删除业务目录、授权保护目录或将空库覆盖到原目录。若无法确认原安装参数，先提供原安装目录中的installation.json核对。

现场怎样复核

  1. 等待管理系统取得新的液位、仪表状态和故障码。确认实际连接的GT6757X网关槽位与管理系统罐号绑定一致，且本罐已开通远程液位修改权限。
  2. 若刚在网关页面执行过一次修改，先核查该次结果，再在网关页面人工复位；正常操作和独立停止通道都应为空闲。复位只清结果，不会恢复原偏移或再次修改液位。
  3. 本次仅由现场一个操作端发起修改。填写经现场核实的目标液位和原因，阅读确认项后执行；不要让网关网页与管理系统同时提交。
  4. 在管理系统“操作记录与回读”核对本次目标、结果和回读记录，并与网关结果、仪表实际液位核对。状态确认只表示偏移回读和认证清零确认，现场精度及断电保存需另行验证。
  5. 若结果未知或提示故障，保留记录并人工核查，不连续重试。不自动补写、不自动复位的规则保持。

验证范围

本版完成292项单元测试及独立模拟网关/浏览器回归，包括可选密度组未启用、实际状态组无效、仪表故障、TCP/RTU、64槽位、目标暂存和提交、结果未知及权限撤销。安装包另做自包含运行、备份恢复和安装预检。六小时连续测试结果另附；真实客户网关上的升级和参数修改需现场人员复核，本地模拟通过不能替代现场结果。
