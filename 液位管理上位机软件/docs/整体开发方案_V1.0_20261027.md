# 液位管理系统整体开发方案

版本V1.0，日期2026-10-27。本文将已确认画面、技术协议和客户回复转为正式软件的开发依据。首期按Windows 10/11、全系统最多配置128罐、常规历史默认60秒保存一次、按一年容量及SQLite规划。先建立并验证基础工程，再分阶段接入已确认业务。原型保留作为画面参考，不直接承接生产控制。

## 1 已确认基线

| 项目 | 本轮采用要求 |
|---|---|
| 操作系统 | Windows 10/11，首期发布win-x64；具体版本和系统缩放在现场验收中记录 |
| 系统容量 | 全系统最多128个已配置罐，含停用罐；不是单串口或单网关128台 |
| 访问方式 | 采集主机本机或局域网浏览器，多浏览器共用后台状态 |
| 数据库 | SQLite，本机磁盘，统一后台访问 |
| 历史 | 默认60秒，每罐独立归档；保留期限按已确认配置，默认12个月，最长一年作为容量基线 |
| 数据量 | 128×1440×365＝67,276,800条常规历史，不含额外事件与任务；自然年跨闰年再增加一天 |
| 控制与测温 | 由后台执行，按设备能力、账号权限、罐级配置和当前状态开放；未知动作不自动重发 |
| 界面基准 | 客户原型V0.10，包括统一事件页及已确认的颜色、罐型、温度和计量显示 |

历史间隔仍保留可配置需求；本轮性能基线为60秒。更短周期的数据量和可支持档位须在容量样机验证后确定，不能把默认周期的测试结论套到1秒或10秒周期。最大罐数在后台校验，浏览器不能绕过。

## 3 语言和框架

| 层次 | 技术 | 说明 |
|---|---|---|
| 业务与通讯 | C#、.NET 10 LTS | 固定SDK和补丁版本；移植既有C#规则和测试，不直接加载旧Framework DLL |
| 后台宿主 | ASP.NET Core、BackgroundService、SignalR | REST查询/操作，实时状态推送；控制台调试、Windows服务交付 |
| 页面 | Vue 3、TypeScript、Vite、Vue Router、Pinia | 组件化迁移原型，罐图、状态色、参数和列表共用 |
| 曲线 | Apache ECharts | 最多5条、同单位共轴、实际点十字标、缺测断段 |
| 数据 | EF Core SQLite与Microsoft.Data.Sqlite | 配置等常规数据使用EF；历史归档独立批量写入模块 |
| Excel | Open XML SDK | 支持模板、校核、版本化入库和查询结果导出 |
| 测试 | xUnit、协议模拟器、Playwright | 逻辑、协议、数据库、服务和页面分层验证 |

客户运行包自包含、前端资源离线打包，不要求客户安装Node、Python或开发环境。安装包与业务数据目录分离。部署兼容性按实际Windows版本验证，不把运行框架生命周期当作所有Windows版本的兼容证明。

## 4 程序结构与扩展

采用模块化单体，一个主要后台服务，内部任务和数据访问分层。初期不增加微服务及额外消息中间件。

- Domain：128罐容量、单位、数据质量、罐容计算、报警规则和测温规划等纯逻辑。
- Application：配置用例、权限、任务、事件、归档、查询与导入导出接口。
- Communication：RTU/TCP传输、直连/IFX/网关适配、寄存器解码及设备能力。
- Infrastructure：SQLite、迁移、备份恢复、文件、账号和服务实现。
- Host：API、SignalR、后台采集与调度、Windows服务和健康诊断。
- Web：所有用户页面及可复用Vue组件。
- SupplierTools：品牌及交付功能配置，独立于客户权限与菜单。

新增设备增加协议适配；新报表依赖统一计量及作业模型；新增对外接口复用同一份带质量和时间的业务数据。数据库访问通过接口隔离，未来更换数据库仍需迁移和验证，不能只更换连接串。

## 5 采集与控制

每个物理串口只有一个持有者，不同通道独立调度。停止请求、测温定位必要读取、普通动作、常规采集及诊断读取分级安排；大型查询/导出不能持有通讯队列锁。配置保存不自动开始采集或写入仪表。

- 直连RS-485：每线最多32台，仪表地址1～243，以适用寄存器读取。
- IFX3W011 L25：本项目一个COM、站号01读取内部1～32罐；COM1/COM2任选，不拆成两个站号。本机侧为RS-232C，不将接口单元的仪表侧线路当成本机接口。
- GT6757X：Modbus TCP或北向RTU，同一Unit ID按内部仪表编号区分；单机能力和实际绑定核对交付点表，不按128罐系统容量修改网关容量或南向端口。
- C01命令3为测量Ⅲ罐底、7为远程密度、4为停止；协议写值与仪表返回模式枚举分开。
- 网关正常动作和独立停止分开记录。动作回显不等于机械完成；超时先查询结果，不自动清零重发。

数据统一为规范单位，带有效性、采集/接收时间及时间可信度。掉线不补0，不把冻结旧值重新标有效；字段级有效性与总体故障分开处理。修改采集绑定后旧读数不能归到新设备。

## 6 计量、温度与报警

当前体积由主罐容表查表并完成已确认修正得到；静压力容积修正＝表中修正量×仪表密度÷参考密度，参考密度默认1000kg/m³且用户可配置。净体积＝当前体积－人工水体积；质量t＝净体积m³×仪表密度kg/m³÷1000。缺失必要输入时留空并说明原因。

20℃标准密度独立输入，不替代仪表视密；标准体积及VCF不自动编造。主表、小数表、静压力修正表分别维护、校核、版本化、批量关联和取消关联；小数表最终组合规则保留待确认。

常用瞬时温度取IR26。ATS与无线浮子互斥；ATS最多16点，所有已配置且正常读出的点参加平均，包含0℃和液面以上正常点；没有有效点则留空。无线浮子按V1.3规划、定位、600秒实际停留、逐点I6、重试、N/M判断、恢复与记录执行；任务一次认证、停留后新读I6的网关最小接口适配列为技术任务。

报警沿用已确认四限、回差、延时、确认/恢复状态与颜色。无效数据不参与阈值计算；已有活动报警不能因数据无效被自动当作恢复。隐藏不影响报警、历史或采集，停用停止该罐采集。

## 7 SQLite与历史设计

数据库仅由主机后台访问，不放网络共享盘。固定含已知WAL缺陷修复的原生SQLite版本并检查运行时版本；WAL与FULL同步，写入有界队列、批量事务、超时及失败告警。控制发送意图与审计先持久化；数据库异常时停止新增需审计动作，保留明确的停止处理路径。

常规历史采用结构化字段及必要索引，按罐ID和时间查询；UTC整数毫秒用于存储，本地时区用于显示。原始通讯整数、规范单位及高精度计量值采用明确倍率，业务计算使用decimal。完整罐容表和配置只在修改时建立不可变版本，历史引用版本并保留当时结果，不逐条重复写整份配置。

实时读数、30分钟实时缓存、默认60秒历史及完整任务/事件分开。分页查询、分批导出、长范围趋势保留实际采样点/缺测；不通过插值伪造测量。归档与日常到期清理分批执行，按备份策略保留有效恢复点；缩短保留期限或大范围人工清理前先备份并记录策略变更。已释放页面优先供后续写入复用，不为每批删除执行全库VACUUM；不能让历史清理删除仍被任务、配置版本和控制核查引用的证据。

业务和历史先以单库建立容量样机；是否需要按月归档/分库以实际压测决定，不预先增加跨库事务及备份复杂度。备份使用一致性API，记录版本、时间范围及散列；恢复前停止采集、保存原库，恢复后校验并保持控制任务不自动重放。

## 8 权限、品牌与对外访问

管理员、运维、查看角色的页面和API权限一致。设置和动作记录操作者、对象、原值/新值、结果、时间及失败原因；统一进入事件记录。供方品牌编辑及功能开通不提供客户入口，后端同时校验交付能力；未交付无线浮子模块的页面和资源按交付构建裁剪，ATS独立保留。

保留已有软件名称、厂家Logo、独立程序图标的交付要求。品牌变化不改变数据目录或库标识。上个项目试用授权与到期限制不默认带入本产品。

默认本机访问，局域网访问在安装中明确开启并设置账号/监听/防火墙；对外接口只读、带质量/时间，不直接暴露数据库或任意仪表写入。公网、云端和移动端维持协议边界。

## 9 验证、交付与风险控制

分为逻辑测试、协议模拟、服务/数据库集成、页面测试、128罐全年容量、安装恢复以及真实设备/现场测试。每项记录输入、版本、结果和限制；模拟结果不等于真机验收。

早期容量样机验证6728万条结构化数据的体积、索引和常用查询；正式字段冻结后做完整最终容量测试，同时采集128罐、查询、曲线、导出、备份及实际恢复。先记录目标电脑配置再确定响应门槛，不预先承诺未经测量的秒级结果。另安排72小时稳定运行、异常退出、磁盘不足、重启恢复与受控断电验证。

分阶段提供可运行工程版、变更说明、检查结果及遗留事项。最终交付离线安装包、使用和部署手册、接口点表、备份恢复说明、现场验收表。具体日历工期在首轮技术样机和设备条件明确后确定，不以未验证日期承诺替代阶段验收。
