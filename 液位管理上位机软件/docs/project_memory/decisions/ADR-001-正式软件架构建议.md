# 正式软件架构建议

## 状态

已采用并实施基础工程。后续用户已要求按128罐、60秒、一年、SQLite整理方案并开始开发，详见ADR-003。本文保留初始选型理由；具体范围和当前实现状态以整体方案、阶段清单及progress为准。

## 背景

新系统需要局域网浏览器、本地串口和TCP采集、设备动作与长时间测温、历史与审计、按客户裁剪交付；既有温度项目提供C#代码和规则基础。图形原型已确认，正式软件需独立于浏览器会话运行。

## 建议选型

- 后台C#与.NET 10 LTS、ASP.NET Core；后台任务使用BackgroundService，同进程提供REST与SignalR。Windows服务正式部署，控制台模式用于调试。
- 前端Vue 3、TypeScript、Vite，Vue Router与Pinia；表格和表单可采用Element Plus，罐图和主要监控组件按现有原型自定义；趋势图使用Apache ECharts。
- 数据库SQLite起步为本期选择，可靠性和容量条件见ADR-002。配置、用户、任务和审计使用EF Core；历史归档通过Microsoft.Data.Sqlite预编译SQL与批量事务写入。统一数据访问边界，避免业务代码依赖特定SQL。
- 时间用UTC整数毫秒存储并转本地时间显示；设备时间可信度另存。计量核心用decimal，库内高精度数据采用明确倍率整数或规范字符串，避免隐式double转换和在SQLite上对decimal字符串排序。
- Excel使用Open XML SDK，打印采用专用打印页；客户端不依赖Office、Node或Python，前端资源随程序离线打包。
- Windows服务携带运行时自包含发布；可选桌面壳只封装同一网页，不能形成另一套业务实现。

## 模块和依赖

采用模块化单体，一个产品、一个主要后台服务，代码分层。初期不引入微服务、消息中间件或分布式部署。

- Domain：数据质量、单位、计量、报警、测温规则，纯逻辑，不依赖页面或串口。
- Application：权限、用例、任务协调、配置版本、事件、导入导出。
- Communication：RTU/TCP传输与Direct、IFX、Gateway协议适配，能力声明与错误解码。
- Acquisition：通道所有权、优先队列、读数质量、重连与采集缓存。
- Infrastructure：SQLite、迁移、归档、备份、文件和认证。
- Host：REST、SignalR、后台调度、Windows服务及可选内部只读接口。
- Web：Vue页面和共用组件。
- SupplierTools：品牌及交付功能包生成，独立于终端客户界面。

## 关键运行规则

同一物理串口只有一个持有者，各通道独立调度。停止、测温定位所需读取、普通操作和后台采集按优先级协调；界面不能独立打开端口。多浏览器共用服务端状态和权限。

直连RTU、IFX L25及Gateway TCP/RTU分别实现协议适配。IFX单COM、单站号读32罐；网关同Unit ID用内部编号区分，北向点表版本与现场容量须核对；上位机不重设网关南向COM。

IR26为常用温度；I6供无线浮子逐点采温；ATS与无线浮子互斥。长任务在后台执行，关闭页面不取消；后台重启不自动继续运动或重发未知动作，现场核查后处理。V1.3的600秒为正式真实时间，模拟时间只用于隔离测试。

网关D2正常动作与独立停止分别管理。命令受理、回读确认与机械到位分开。未知结果人工核查并留档后才能复位；先写持久化发送意图，再发动作，避免恢复后重复执行。

实时采集与画面推送、30分钟实时缓存、默认60秒历史归档分离。报警与质量变化、测温过程与操作审计完整记录。历史保存当时净体积、质量、输入和表版本，后改配置不重算旧记录。完整配置和罐容表按变更建立不可变版本，历史引用版本，不逐条重复保存整份配置或罐容表。

主表与静压力修正按已确认公式；小数表组合和VCF待明确规则，不补造结果。报表模块保留三类暂未启用入口，后续接入独立的作业模型和模板。

数据库只放采集主机本地磁盘，由服务访问；其他电脑走API。写入队列有界，任务/控制审计优先；导出分页，曲线降采样保留实际点且显式区分聚合，不做伪造插值。备份采用在线一致性快照，恢复必须验证完整性和版本。

## 扩展与限制

增加设备时实现对应协议适配，不修改页面；增加报表按模块扩展；DCS等对外接口只复用业务数据，不各自重算。首期只实现协议约定的一种接口，其他列为后续。

品牌与交付功能由供方生成。客户管理员没有品牌编辑或功能开通入口；后端同时校验模块和权限，未交付模块可从前端构建产物裁剪。2026-10-27用户后续已明确增加到期授权，按ADR-004采用；旧客户授权和私钥不复制。英文支持作为最后P8开发。

SQLite适合先部署单采集主机；现行128罐一分钟一条全年67,276,800条，须用实际字段做全年容量、并发查询、任务与备份测试后定档。大型站点或多服务并发写入可迁移PostgreSQL，但仍需专门的数据迁移和性能验证，不承诺换连接串即可完成。

上个项目优先移植纯规则、协议编解码和测试；WPF界面、旧数据库迁移、旧授权、旧系统约束不能整包照搬。网关Go项目独立保留，通过Modbus与新上位机对接。

## 实施顺序

1. 结合Windows版本和首期设备规模落定架构，配置固定SDK、依赖锁定和独立构建环境。
2. 建立解决方案与协议模拟器；验证四种接入、质量标识与异常恢复。
3. 实现配置、实时页面、计量、报警、历史与统一事件，做不可变历史和全年容量验证。
4. 接入仪表动作、ATS和无线浮子测温，完成所需网关接口适配，现场校验真实响应和停止偏差。
5. 权限、到期授权与供方交付裁剪、内部只读接口、备份恢复、中文包及目标Windows/DPI验收。
6. 最后完成英文支持、双语回归和最终离线交付；现行顺序见V1.1阶段清单与ADR-004。

测试计划包括xUnit逻辑测试、协议模拟器集成、临时SQLite库迁移/恢复与Playwright界面测试。模拟与真机结果分别记录。
