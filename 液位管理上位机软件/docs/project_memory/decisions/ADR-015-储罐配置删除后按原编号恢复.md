# ADR-015：储罐配置删除后按原编号恢复

## 状态

2026-11-07，按用户反馈完成r22-u2修复。本机已更新，用户仍须自己核对并确认导入。

## 背景

用户在本机r22导出“储罐配置 (8).xlsx”，删除全部储罐并保存后导回，13行均被拒绝“内部编号不存在”，并级联提示罐组未在主表列出。原文件未修改，SHA256 ef24fbbd2d2d0a5ab70470cf5addd8060a1acf0d618debc423f60c1de5ab298e。

原导入器要求填了内部编号的行必须已存在，遗漏删除后恢复场景。原测试只覆盖现有罐更新与清空编号后新增，没有覆盖这个实际往返过程。

## 决策

- 有效且不重复的原内部编号在当前不存在时，允许作为恢复/新增身份，保留该GUID，以继续关联旧历史。不得一律生成新GUID。
- 内部编号已存在则更新原身份。罐号已属于其他内部编号时拒绝，不按同罐号静默覆盖。新建罐留空编号时仍按罐号匹配已有罐，或者生成新身份。
- Guid.Empty、格式错误、重复编号、重复罐号、无效通道/表引用、超128罐及预览并发/权限等校验保留。
- “罐组关联”只应用于成功解析的主表行。主表有错误时不再用误导性的“未列出”重复报错；真正没有主表行的关联仍报错。
- 旧TANK-CONFIG-1/2/3模板保持兼容，原表头不变。新导出的填写说明解释恢复时保留原编号，以及引用资料须预先存在。

## 验证

- 新增4项回归：全删恢复原ID与多组、部分删除/未列出罐保留、非法ID无级联错误、重复恢复ID拒绝。修复前3项实际失败，修复后完整428项通过。
- 用户原13罐Excel在独立本机回环后台实测：零罐直接预览/保存13罐及18个关联；实际导出→全删保存→真实页面上传并确认恢复，各导出字段/原ID/多组一致，原历史仍按原ID查询；删除1罐再导入恢复1/更新12；重复导入不新增，旧版本预览提交409。无真实串口、无控制写入，原Excel与现用配置未改。
- 完整包原生10组文件哈希/独立运行/WebView2桌面/离线恢复/安装预检通过。原r18到r22的直接升级证据沿用，schema17和升级机制未改；本修复未重跑r18升级或新增六小时长测。
