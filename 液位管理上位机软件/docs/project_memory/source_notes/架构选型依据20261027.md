## SQLite可靠性补核

- 用户2026-10-27明确先支持Windows 10/11，询问大量历史数据下SQLite可靠性。
- 已查阅上个温度浮子项目docs/P8历史归档与六个月容量验证记录_20261017.md：64罐183天共16,865,280条，实际库8,978,075,648字节约8.36GiB；旧V8结构包含额外归属关联，完整性、并发统计/备份和实际恢复有记录。本轮没有重跑这些测试，不代表新系统性能或实机运行结论。
- SQLite官方同步说明：WAL配合NORMAL可能在系统崩溃或掉电时丢失最近已提交事务；WAL配合FULL提供提交同步，仍依赖存储设备正确执行同步。https://sqlite.org/pragma.html#pragma_synchronous
- SQLite官方WAL说明第11节：WAL-reset低概率并发缺陷在3.51.3及后续修复，3.44.6和3.50.7有回补。新工程必须核对实际加载原生引擎的修复状态，不能仅看.NET包号。https://sqlite.org/wal.html
- 官方强调SQLite可抵抗一般崩溃，但存储硬件、关闭同步、错误文件操作和已知缺陷仍可能导致损坏。https://sqlite.org/howtocorrupt.html
- 数量估算按365天：64罐60秒归档33,638,400条；10秒201,830,400条；1秒2,018,304,000条。均不包括报警、任务和额外事件记录。
