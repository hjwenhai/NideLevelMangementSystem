## 问题和修改

- `设备采集网关/protocols/north-v3.json`：group2为IR49～52的density_status快速组；group4为IR33～48的可选16点densities组。摘要S+9（IR51）、S+10（IR52）应使用group2的成功/错误/年龄校验。
- r12 `DeviceReaders.cs`误用 `G(4,4)` / `G(5,4)`，可选group4未采集、不支持、失败或过期时，把有效仪表状态和故障码变成null；反向还可能把真实状态组过期误报有效。改为 `G(4,2)` / `G(5,2)`，保留摘要字段有效位、真实组质量和年龄校验。
- `ControlService.RequestAsync`是在创建控制记录和参数写入前拒绝请求；原截图不能据此判断曾写偏移。改用纯域校验 `ControlReadiness`，明确列出无效液位/浮子位置、仪表状态、故障码及已有原因，保留Stop入口。
- 网关远程液位修改为参数校准，按厂家 `src/internal/command/level.go` 与文档28流程，不以IR51 bit15作为网关参数写入许可。上位机 `RemoteLevelDriver.Fresh`对网关命令11移除该浮子运动远程位条件，仍要求新鲜液位、状态/故障正常、启动及绑定不变；直连RTU保留原远程模式检查。没有改普通运动命令/自动测温权限。
- 未改网关固件、网关工程、原协议或现有客户数据/授权。接口地址、参数范围、FC10暂存/FC06提交、结果未知不重发、故障/权限/授权及通道空闲校验保留。
